# ADR-0018: UI на GPUI вместо egui/eframe/wgpu

Статус: **принято владельцем 2026-10-19** (базис Pets, `claude/ADR-GPUI.md` в Project). Заменяет: ADR-0 (стек egui/eframe), ADR-0011 (`Ui::show(&egui::Ui)`), ADR-0012 (wgpu DX12), S0-decisions №46 (syntect) и №50 в части бэкендов.

## Контекст
Сравнение egui (wgpu DX12/Vulkan) и GPUI (DX11) на сборке ThePostman (50 тыс. строк) и бенче-панели (35 тыс. строк), стенды Intel iGPU 144 Гц и RTX 5060 180 Гц, медианы чередующихся прогонов:

| Метрика (Intel) | egui DX12 | GPUI (кэш view) |
|---|---|---|
| p99 кадра, листание | 9,8 мс (всплески до 37) | **8,8 мс** |
| p99 ресайза | 38–56 мс | **12–13 мс** |
| Память процесса | 376 МБ | **197 МБ** |
| CPU UI-потока / процесса, листание | 44,5 / 46,5 % | 48 / 58,5 % |
| CPU в простое | 0 % | ≤ 0,5 % (после исправления) |

Первый кадр > 1 с у обоих — проблема старта, не фреймворка.

## Решение
- UI — **GPUI** + **gpui-kit** (версии фиксируются в `[workspace.dependencies]`; источник — crates.io, при необходимости `[patch]` на gpui-ce).
- Модель: кэшируемые view (`Entity`) по зонам экрана — панели, табы, cmdline, keybar, тосты, оверлеи; перерисовка только изменившихся; в простое — ноль кадров.
- Core остаётся владельцем состояния и Command bus; живёт в `Entity<CoreHost>`. Воркеры будят UI через канал → `cx.notify()` на затронутых view. Контракт `Ui::show(&egui::Ui …)` (ADR-0011) заменяется адаптером «снапшот AppState → view»; `Command`, `UiEvent`, `Focus`, keymap-реестр — без изменений.
- Рендер на Windows — DX11 (бэкенд GPUI). `ui.renderer = auto | warp` — если GPUI поддерживает `D3D_DRIVER_TYPE_WARP`; иначе патч/issue, опция временно скрыта.
- Ввод: keymap S3 (пресеты, контексты, аккорды, раскладка-независимость v4 №5) отображается на actions/key contexts GPUI; реестр команд и TOML-формат не меняются.
- Редактор и подсветка (S7) — на редакторе gpui-kit, tree-sitter (№53). Терминал (S6) — `alacritty_terminal` + отрисовка GPUI (прецедент Zed).
- Визуал — своя тема Fluent поверх gpui-kit (№56).

## Перф-гейт (обязателен для мержа G-задач)
- CPU в простое ≤ 0,5 %; p99 кадра при листании ≤ 9,5 мс; p99 ресайза ≤ 13 мс.
- CPU при листании: процесс ≤ egui +30 %, UI-поток ≤ egui +10 % (базовая линия — последняя egui-сборка, тег `egui-final`).
- Бинарь ≤ 25 МБ (№54); память процесса private ≤ 200 МБ.

## Последствия
- Спеки S2/S3/S7 требуют ревизии; до неё «egui/eframe/wgpu» в них читать как «GPUI», противоречия решает этот ADR.
- egui/eframe/wgpu удаляются из графа зависимостей в G-06. Перед удалением — тег `egui-final` для базовой линии бенчей.
