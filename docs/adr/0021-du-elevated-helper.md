# ADR-0021: Досчёт размеров с правами администратора

Статус: предложено, ждёт владельца (связано с S0-decisions №81, №84; F-01 в `docs/01-ROADMAP.md`; ADR-0020)

## Контекст
Анализ места (F-01) работает в процессе Урфина без прав: часть каталогов (`System Volume Information`, чужие профили, `WindowsApps`, каталоги с запрещающим ACL) не читается — вкладка `du:` показывает «нет доступа: N папок», их размер не учтён. Пользователь хочет нажать «Досчитать с правами администратора» и получить полную картину, не перезапуская Урфин.

Операции (S5) повышения прав не имеют — и это принцип: всё, что меняет данные, выполняется в процессе пользователя. Досчёт не должен этот принцип нарушить.

## Варианты
**(а) Перезапуск всего Урфина от администратора.** Отвергнут: ради чтения метаданных под полным токеном оказываются GPUI, терминал (ConPTY, дочерние процессы), операции записи/удаления, плагины, буфер обмена и drag&drop; перетаскивание из Проводника в повышенное окно не работает (UIPI); теряется состояние сессии. Несоразмерно задаче.

**(б) Отдельный процесс-помощник `urfin-du-helper.exe`.** Маленький бинарь только для чтения метаданных: получает список корней, отдаёт поток записей по именованному каналу, завершается. Режим `urfin.exe --du-helper` отвергнут: повышенный процесс отобразил бы весь код Урфина и грузил бы DLL из его каталога (там `conpty.dll` — №84), поверхность та же, что в (а).

**(в) Привилегия `SeBackupPrivilege` внутри помощника.** Членство в Администраторах не даёт читать каталог с запрещающим ACL; Backup-привилегия + `FILE_FLAG_BACKUP_SEMANTICS` даёт перечисление в обход ACL на чтение. Без (в) помощник упрётся в те же «нет доступа».

**(г) Чтение тома: `FSCTL_ENUM_USN_DATA` (+ записи MFT).** Быстрый полный обход NTFS: дерево по FRN/родительскому FRN. Размеров в `USN_RECORD` нет — их даёт разбор записей MFT (`FSCTL_GET_NTFS_FILE_RECORD` или чтение потока `$MFT`), то есть разбор дисковых структур в повышенном процессе и дескриптор `\\.\X:` на чтение, технически позволяющий читать содержимое файлов. Выигрыш — на целом томе, не на десятке папок.

## Решение
(б) + (в) по умолчанию; (г) — отдельной опцией ускорения после замеров, выключена по умолчанию, только для корня NTFS-тома.

### Помощник
- Отдельный bin-крейт `crates/duhelper` (`urfin-du-helper`): зависимости — `windows-sys`, протокол; без gpui, ops, term, ui, view. Бюджет: бинарь ≤1,5 МБ, старт <50 мс. `unsafe` — только в `duhelper::sys` (дополнить список в CLAUDE.md).
- Манифест `requireAdministrator`; запуск из Урфина — `ShellExecuteExW`, verb `runas`, `SEE_MASK_NOCLOSEPROCESS` (берём `hProcess` и PID). Отказ в UAC (`ERROR_CANCELLED`) — сообщение «Отменено», ничего не досчитано.
- Только чтение метаданных: имя, размер, занятое место, атрибуты, время изменения, тип. Каталоги открываются `FILE_LIST_DIRECTORY | SYNCHRONIZE` + `FILE_FLAG_BACKUP_SEMANTICS | FILE_FLAG_OPEN_REPARSE_POINT`, перечисление — `GetFileInformationByHandleEx(FileIdExtdDirectoryInfo)`. Файлы на `FILE_READ_DATA` не открываются никогда. Ссылки (junction, symlink, mount point) не раскрываются — как во всех обходах S4.
- Ни одного вызова записи, удаления, смены атрибутов, ACL, владельца. Сам помощник не пишет файлов (в т. ч. логов в `%LOCALAPPDATA%` — запись повышенным процессом в каталог пользователя = атака через ссылки).

### Укрепление процесса (при старте, до разбора аргументов)
- `SetDefaultDllDirectories(LOAD_LIBRARY_SEARCH_SYSTEM32)`; импорт только системных DLL.
- `SetProcessMitigationPolicy`: запрет дочерних процессов, динамического кода, загрузки образов с удалённых путей и низкой целостности, точек расширения (AppInit и т. п.), строгая проверка дескрипторов.
- Токен: включить `SeBackupPrivilege`, остальные привилегии удалить (`SE_PRIVILEGE_REMOVED`): Restore, TakeOwnership, Debug, Security, Impersonate и прочие.
- Политика перечитывается самим помощником из HKLM (не доверяем проверке Урфина); запрещено — выход с кодом.
- Живёт до конца подсчёта: выход по `Done`, обрыву канала, смерти родителя (ожидание на его дескрипторе) или простою 30 с без подключения.

### Канал и проверка сторон
- Имя `\\.\pipe\urfin-du-{GUID}` (GUID — новый на запуск), передаётся в аргументах вместе с PID Урфина и одноразовым nonce (128 бит).
- Сервер — помощник: `FILE_FLAG_FIRST_PIPE_INSTANCE`, `PIPE_REJECT_REMOTE_CLIENTS`, одно подключение. DACL: SID пользователя и logon-SID сеанса, взятые из токена процесса Урфина (не из аргументов) — работает и при вводе учётки другого администратора в UAC; метка целостности medium, чтобы клиент без прав мог подключиться.
- Помощник проверяет клиента: `GetNamedPipeClientProcessId` == PID из аргументов; образ этого процесса (`QueryFullProcessImageNameW`) — `urfin.exe` из того же каталога, что и помощник, с действительной подписью того же издателя; первое сообщение содержит nonce. Любое несовпадение — разрыв и выход.
- Урфин проверяет сервер: `GetNamedPipeServerProcessId` == PID из `hProcess`.

### Протокол
Версионированные кадры (длина + тип), один запрос на жизнь процесса:
`Hello{version, nonce}` → `Scan{roots[], use_mft}` → поток `Entry{parent, name, size, alloc, attrs, mtime, kind}` / `Denied{path, code}` / `Progress` / `Log{level, msg}` → `Done{totals}`. Других команд нет; неизвестный тип кадра, превышение лимитов — разрыв.

Валидация корней в помощнике: ≤64 корня; абсолютный путь на локальном томе (`GetDriveTypeW` — FIXED/REMOVABLE); запрещены UNC и сетевые диски (у повышенного токена своих сопоставлений нет, плюс риск relay), `\\.\`, `\\?\GLOBALROOT`, ADS (`:` после буквы диска), `..` после нормализации; длина ≤32 767. Корень — каталог, не точка повторной обработки.

### Урфин (процесс без прав)
- Пункт «Досчитать с правами администратора» — только при «нет доступа: N > 0»; корни — ровно эти N папок, не весь диск.
- Записи от помощника помечены `elevated`: в списке и на карте видны, но F8 и отметка для них недоступны (подсказка «нет доступа — удалить нельзя»), в «освободится X» не входят. Удаление по-прежнему только в процессе пользователя, и недоступное не удаляется.
- Кэш `du` на диске хранит для повышенных поддеревьев только итог (путь недоступной папки, размер, число элементов, дата), без имён внутри: имена из чужих профилей не оседают в каталоге пользователя. Детали — только в памяти, до закрытия вкладки.
- Журнал (tracing): запуск, результат UAC, PID помощника, число корней, режим (ACL/MFT), длительность, итоги, ошибки и `Log` от помощника. В установленной (не portable) версии — также событие в журнал Windows Application (источник `Urfin`) о запуске/завершении с SID и корнями — для SOC.

### Подпись и подмена бинаря
- Сборка дистрибутива подписывает `urfin.exe` и `urfin-du-helper.exe` (Authenticode, один издатель). UAC показывает проверенного издателя.
- Перед запуском Урфин открывает помощник с `FILE_SHARE_READ` (без записи и удаления — защита от подмены между проверкой и запуском), проверяет `WinVerifyTrust` и совпадение издателя со своим. В release неподписанный помощник не запускается (отказ закрыт); в debug — проверка пропускается с `warn`. Важно для portable: каталог доступен пользователю на запись, без проверки подписи вредонос мог бы подложить свой exe под согласие UAC.

### Политика организации (дополнение ADR-0020)
| Значение | Тип | Смысл |
|---|---|---|
| `du_elevated_helper` / `DuElevatedHelper` | DWORD | 0 — досчёт с правами запрещён: пункт с замком, помощник сам откажется; 1/нет — разрешён |
| `du_elevated_mft` / `DuElevatedMft` | DWORD | 0 — режим (г) запрещён; 1/нет — по настройке пользователя |

## Последствия
- Новый процесс и бинарь в дистрибутиве; межкрейтовые контракты не меняются (протокол — внутренний тип `duhelper`, флаг `elevated` — в модели F-01, спека ещё не написана).
- Остаточный риск: процесс без прав видит имена и размеры в защищённых каталогах выбранных корней — это то, на что пользователь дал согласие в UAC; на диск это не попадает.
- Режим (г) расширяет поверхность (разбор MFT, дескриптор тома) — поэтому выключен по умолчанию и под отдельной политикой.
- Нужен сертификат подписи кода — вопрос владельцу; без него функция в release недоступна.
- Строки UI — urfin-i18n (EN+RU); новая команда (`du.elevate`, предварительно) — в docs/COMMANDS.md.

## Задачи
1. **DU-H1** — крейт `urfin-du-helper`: укрепление процесса, Backup-привилегия, канал с DACL и проверкой сторон, протокол, валидация корней. Тесты: разбор кадров (включая мусор и превышение лимитов), валидация путей, отказ при чужом PID/nonce.
2. **DU-H2** — интеграция в F-01: команда, запуск через `runas`, проверка подписи, слияние записей `elevated`, запрет F8/отметки, кэш только итогов, политика `DuElevatedHelper`, журнал, i18n, COMMANDS.md. Метка `win-manual`.
3. **DU-H3** (после замеров DU-H2) — режим (г) USN+MFT для корня NTFS-тома, политика `DuElevatedMft`; принимать, только если на целом томе быстрее (б)+(в) в разы.
4. **DU-H4** — шаг сборки дистрибутива: подпись обоих exe, проверка в CI, что у помощника нет импортов вне System32.

## Проверить на стенде (L0/L2)
- UAC: согласие, отказ, ввод учётки другого администратора — канал подключается, DACL выдан пользователю Урфина.
- Каталоги `System Volume Information`, `C:\Users\<другой>`, `C:\Program Files\WindowsApps` — досчитаны; «нет доступа» исчезает; F8 на них недоступен.
- Подмена `urfin-du-helper.exe` неподписанным/чужим — запуск отклонён до UAC.
- Подключение к каналу посторонним процессом того же пользователя — отказ, помощник завершается.
- Закрытие вкладки / `job.cancel` / убийство Урфина — помощник выходит ≤1 с; в Диспетчере задач не остаётся.
- `DuElevatedHelper`=0 — пункт с замком; ручной запуск помощника с корректными аргументами — отказ.
- Process Explorer: у помощника из привилегий только Backup, нет дочерних процессов, загружены только системные DLL; Procmon — ни одной записи в ФС.
- Кэш `%LOCALAPPDATA%\Urfin\state\du\` — нет имён изнутри защищённых каталогов.
- Замеры: время досчёта для 10–50 недоступных папок; размер бинаря помощника.
