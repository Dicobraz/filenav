# ADR-0019: символ без своей клавиши в раскладке — по месту US-QWERTY

Статус: предложение (S3-11, 2026-10-20), ждёт решения владельца. В коде не сделано.

## Контекст

Правило v4 №5: если раскладка даёт на клавише латинский символ — сочетание по нему, иначе — по месту US-QWERTY. Матрица S3-11 (`crates/ui/src/gpui_shell/input_matrix_tests.rs`) показывает одно сочетание, которое по этому правилу недостижимо:

- **QWERTZ, `Ctrl+]`.** `]` в немецкой раскладке есть только с AltGr (AltGr+9 = Ctrl+Alt+9 — это ввод символа, S3 §0). На месте `]` US стоит `+` — латинский символ, и сочетание идёт по нему: `Ctrl+Plus`. Привязка `Ctrl+CloseBracket` (base: `cmdline.insert_name side=right`) с этой раскладки не вызывается никак.

У `[` в QWERTZ (`ü`) и у `[ ]` в AZERTY (мёртвая `^`, `$`) символ — не клавиша keymap, поэтому срабатывает место US, и они работают. Остальные раскладки матрицы проблемы не имеют.

## Предложение

Дополнить правило: если сочетание по надписи не привязано, а надпись — символ (не буква и не цифра), искать сочетание по месту US-QWERTY. `Ctrl+(+)` в QWERTZ: `Ctrl+Plus` не привязан → `Ctrl+CloseBracket`.

Буквы и цифры не трогаем: в Dvorak `Ctrl+J` на месте `C` не должен давать `Ctrl+C`.

Реализация — в `KeyInput::code`/`feed` (keymap), как запасное сочетание `fallback` у `NumEnter` → `Enter`.

## Альтернативы

- **Оставить как есть.** В QWERTZ `Ctrl+]` недостижим; пользователь переназначает его в `user.toml`. Матрица держит его в списке `GAPS`.
- **Всё по месту US, когда символа нет без модификаторов.** Требует знать всю раскладку (какие символы есть на клавишах без Shift) — в keymap этого нет.

## Последствия

- Меняется правило v4 №5 (контракт) — нужна запись в S0-contracts.
- Символ на клавише получает вторую роль, только если своей привязки у него нет: `Ctrl+Plus` пользователя в QWERTZ по-прежнему важнее.
- Из `GAPS` матрицы убирается QWERTZ `]`.
