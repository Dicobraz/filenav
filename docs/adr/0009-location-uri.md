# ADR-0009: строковая форма `Location` (uri)

Статус: принято (S1-03, 2026-10-15; подтверждено владельцем 2026-10-15). Источник: S0-contracts-v5 №8 (ADR-0008) — формат экранирования там не задан.

## Контекст

uri `Location` — сериализованная форма в `session.toml` и в аргументах команд. Цепочка контейнеров записывается через `>>` (`local:C:\a.zip>>zip:/in`), поэтому `>>` в именах файлов надо экранировать обратимо. Глубина цепочки `outer` ограничена 8.

## Решение

1. Формат: сегменты `backend:path` от внешнего контейнера к внутреннему, через `>>`.
2. Backend — идентификатор `[a-z0-9][a-z0-9+.-]+`, минимум два символа (чтобы `C:\x` не читался как backend `C`), не экранируется.
3. Путь экранируется процентами, hex в верхнем регистре:
   - `%` → `%25`, `>` → `%3E` (каждый `>`, не только пары: иначе `a>` + `>>` неоднозначно);
   - байты, не входящие в корректный UTF-8 (unix), → `%HH` по одному;
   - всё остальное, включая `\`, `:` и пробелы, пишется как есть.
4. Разбор: `split(">>")`, в каждом сегменте backend до первого `:`. Принимается любой `%HH`; неполный `%`, не-hex и одиночный `>` — `LocError::BadEscape`. Больше 9 сегментов (глубина `outer` > 8) — `LocError::TooDeep`. Путь backend `local` нормализуется как в `Location::local`.
5. Windows: путь хранится как UTF-8. Пути с непарными суррогатами в uri не переживают roundtrip (`LocError::BadPath` при разборе); на unix roundtrip полный для любых байтов.

## Последствия

- `>>` в uri всегда разделитель; имена с `>>`, `>`, `%`, `\` проходят roundtrip (unit + proptest в `core::loc`).
- Обычные пути читаются глазами без изменений: `local:C:\Program Files\x`.
- Формат — контракт сессии: менять только новым ADR с миграцией `session.toml`.
