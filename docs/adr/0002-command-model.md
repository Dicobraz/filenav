# ADR-0002: модель команд

Статус: принято (S1, 2026-10-14). Источник: specs/S1.md §0, §2.2. Уточнения: S0-contracts-v2 №11, v3 №5/№14, v5 №4/№6 (ADR-0004, 0006, 0008).

## Контекст

Ввод приходит из keymap, палитры, cmdline, терминала, watcher и в будущем макросов. Сессии S3–S8 добавляют свои команды и не должны править enum в core.

## Решение

1. На проводе одна форма: `Command { id: CommandId, args }`. `CommandId` — строка вида `namespace.action[.sub]`.
2. Handlers регистрируются по namespace (часть id до первой точки). Core разбирает свои команды в типизированный `CoreCmd`.
3. Команда сериализуется в TOML (`"id"` или `{ cmd = "id", arg = … }`) и разбирается из текста (`panel.go path="C:\x y"`). Это единый вид для keymap, палитры, cmdline и макросов.
4. `CommandRegistry` хранит `CommandMeta`/`ArgSpec` и валидирует аргументы. Набор `Value`: `Bool`, `Int`, `Str`, `Loc`, `List` (`Value::Text` не вводится, ввод редактора идёт через `ViewInbox`).
5. Аргумент `side` принимает `left | right | active | passive`. `Args::side` возвращает `SideRef`, перевод в `Side` делает вызывающий код.
6. Подписи команд берутся из Fluent: `cmd-<id>` и `keybar-<id>` (точки id заменены дефисами). Поля подписи в `CommandMeta` нет.

## Последствия

- Новые команды не требуют изменений в core. Новые namespace не требуют S0, новые варианты общих enum требуют.
- Сравнение строк id на частоте ввода ничего не стоит.
- Ошибки аргументов ловятся на `validate` (`CmdError`), а не в handler.
