# ADR-0015: где действует контекст `global` keymap

Статус: принято (владелец, 2026-10-18, при S3-02).

## Контекст

Два источника противоречат друг другу:
- **S3 §2.4 и приёмка S3-02.** `global` истинен в `panel|cmdline|viewer|editor` и ложен в `terminal|prompt|overlay`.
- **Контракт v3 №2.** В `Overlay`, `Cmdline` и `Terminal` keymap поглощает привязки своего контекста и привязки `global`. v5 №2 то же говорит для `Editor`.

По контракту глобальные клавиши (F10, Ctrl+Tab…) перехватывались бы и у программ в терминале: vim, mc, ssh. По S3 они молчали бы при открытом меню, быстром поиске и переименовании.

## Решение

`global` истинен в `Panel`, `Cmdline`, `Viewer`, `Editor` и `Overlay(*)` и ложен в двух фокусах:
- **`Terminal`** — там действуют только явные привязки контекста `terminal`, остальное уходит в PTY;
- **`Prompt`** — вопрос (Да/Нет, конфликт копирования) обрабатывает свои клавиши, глобальные не срабатывают.

## Последствия

- Контракт v3 №2 для `Terminal` читать с этой поправкой: только `terminal`, без `global`. Для `Overlay` и `Cmdline` всё совпадает с контрактом.
- В S3 §2.4 строку про `global` читать по этому ADR, а в приёмке S3-02 — «`global` ложно в `terminal`, `prompt`».
- Привязки `global` не должны забирать клавиши, нужные полям ввода в оверлеях (буквы, Ctrl+A/C/V в тексте). Такие сочетания пресеты держат в контексте `panel`; при конфликте предупреждает компиляция keymap (S3-04).
