## 0. Ключевые решения

- **Решение:** VT-эмуляция строится на `alacritty_terminal = "=0.26.0"` (Apache-2.0, внутри vte 0.15). Используем только `Term` и `vte::ansi::Processor`. Его `tty` и `EventLoop` не используем.
  **Почему:** готовые сетка с reflow, скроллбэк, alt-screen, выделение (simple/semantic/line/block), damage-трекинг, regex-поиск, DEC 2026 sync, kitty keyboard и OSC 52 — это месяцы работы, если писать на голом vte. Цена — две вещи. Первая: OSC 7/133/633 у него `unhandled`, поэтому ставим свой пре-сканер (§2.3). Вторая: API 0.x меняется, поэтому версия пинится точно, а апгрейд оформляется отдельной задачей. termwiz (wezterm) отклонён: тяжелее, последний релиз 2025-03, API рассчитан на wezterm.
- **Решение:** PTY — своя тонкая обёртка `term::sys::{conpty, unix}` на `windows-sys 0.61` и `rustix 1.1` + `rustix-openpty 0.2`. Это единственное место с `unsafe` в крейте.
  **Почему:** portable-pty 0.9 (последний релиз 2025-02) тянет winapi, nix 0.28, lazy_static, shared_library и serial2, в нём нет job object и `ReleasePseudoConsole`. У tty из alacritty `Drop` блокируется на `child.wait()` (unix), на ошибку `CreatePseudoConsole` срабатывает `assert_eq!` (паника), и он завязан на polling-EventLoop. Нам нужны свой порядок закрытия ConPTY (без дедлоков), sideload `conpty.dll`, job object (busy-детект, kill дерева) и блокирующее чтение в `spawn_dedicated`. Всё это ≈600 строк.
- **Решение:** ConPTY загружается так: сначала `conpty.dll` + `OpenConsole.exe` рядом с exe (NuGet `Microsoft.Windows.Console.ConPTY` ≥1.22, MIT), затем fallback на kernel32. `dwFlags = 0`: без `PSEUDOCONSOLE_INHERIT_CURSOR` (вешает ввод до ответа на DSR), без RESIZE_QUIRK и WIN32_INPUT_MODE. Режима passthrough не используем, он недокументирован и в ConPTY 1.22+ не нужен. `ReleasePseudoConsole` определяем через `GetProcAddress`. Источник ConPTY задаётся настройкой `term.conpty = "auto"|"bundled"|"system"`.
  **Почему:** переписанный ConPTY 1.22 сохраняет порядок неизвестных OSC относительно текста, быстрее (до 2× на SGR, до 16× на plaintext) и не ломает reflow. Встроенный в старые сборки Windows переставляет OSC, а от них зависят границы промпта. Zed и wezterm делают так же (Решение для владельца №3).
- **Решение:** на каждый shell — свой PTY-сеанс. Сеансы лежат в глобальном пуле и не привязаны к табам панелей. Активен один сеанс, остальные живут в фоне со своим скроллбэком. Сеанс запускается лениво, а shell по умолчанию прогревается после первого кадра.
  **Почему:** PTY на таб стоил бы 60–100 МБ RAM на каждый pwsh и ломал бы модель Far, где одна консоль. Пул даёт переключение shell на лету без потери вывода, а `term.new` позволяет держать второй сеанс того же shell (например, сервер).
- **Решение:** гибрид «cmdline + PTY». В фазе `Prompt` (shell ждёт ввод, интеграция подтверждена) клавиши идут в **свой** line-editor. Enter пишет `текст\r` в PTY, shell сам эхает команду в транскрипт. В фазах `Running`, alt-screen и `NoIntegration` действует **raw**: все клавиши, кроме зарезервированных, уходят в PTY.
  **Почему:** своя строка даёт Far/DN-функции (история Alt+F8, автокомплит, Ctrl+Enter, работа при фокусе на панели), а живой shell — честную семантику (алиасы, профили, `cd`, переменные). Транскрипт выглядит как в Far: промпт + команда + вывод.
- **Решение:** shell integration встраивается автоматически, без правки файлов пользователя. Для pwsh — `-EncodedCommand`, для cmd — env `PROMPT`, для bash — `--rcfile`, для zsh — `ZDOTDIR`, для fish — `--init-command`, для WSL — `WSLENV`. Протокол — OSC 633 (A/B/C/D/E/P), cwd передаётся как `633;P;FnCwd=<nonce>;<path>`. Парсим также чужие OSC 133, OSC 7, OSC 9;9 и OSC 1337 CurrentDir (fallback).
  **Почему:** 633 — надмножество 133 (есть E с командной строкой и P со свойствами). Nonce защищает от подмены cwd/промпта выводом недоверенного контента (`cat` файла, ssh). `-EncodedCommand` не попадает под ExecutionPolicy и GPO AllSigned.
- **Решение:** cwd синхронизируется лениво в направлении панель→shell: перед выполнением команды, по Ctrl+O и при входе в raw. Делается это «тихим cd» через скрытую клавишную привязку в shell (pwsh/bash/zsh/fish) без эха. Для cmd — видимый `cd /d` (для UNC — `pushd`). В направлении shell→панель синхронизация мгновенная, по FnCwd.
  **Почему:** на каждую навигацию по панели ничего не пишем в PTY. Транскрипт и история остаются чистыми, гонок нет.
- **Решение:** терминал рисуем на атласе шрифтов egui. Каждая строка превращается в `Arc<Mesh>` и кэшируется по damage. Фоны сливаются в прямоугольники по runs. Box-drawing, блоки и Powerline рисуются процедурно. Свой GL-атлас через `PaintCallback` — запасной план, если не уложимся в бюджет.
  **Почему:** решение не зависит от бэкенда (glow сейчас, wgpu потом) и использует один атлас с UI. При неизменной сетке кадр почти ничего не стоит.

## 1. Архитектура крейта `urfin-term`

Зависимости: `urfin-core`, `alacritty_terminal`, `windows-sys` (cfg windows), `rustix` + `rustix-openpty` (cfg unix), `base64 0.22` (то же, что у alacritty), `unicode-width 0.2`, `compact_str`, `crossbeam-channel`, `serde`, `toml`, `tracing`, `thiserror`. Крейт **не зависит от egui**. Виджет живёт в `urfin-ui::term` (модуль владения S6, см. Запрос к S0 №2).

```
crates/term/src/
  lib.rs        — TermHandler (ns term, cmdline), TermState (в AppState.ext), регистрация
  config.rs     — [term], [term.history], [term.complete], [[term.shells]]
  shells/       — discover.rs (Windows/unix/WSL), spec.rs (ShellSpec, ShellKind, PathStyle), quote.rs
  integ/        — scripts/{urfin.ps1, urfin.bash, zsh/.zshenv…, urfin.fish}, inject.rs, protocol.rs (FnCwd, nonce)
  session/      — manager.rs (пул), session.rs (Phase, марки), reader.rs, writer.rs, scan.rs (OSC-пре-сканер)
  vt/           — shared.rs (FairMutex<Vt>), snapshot.rs (GridSnapshot для UI), input.rs (key/mouse/paste → байты)
  line/         — editor.rs (LineEditor), history.rs, complete/{paths, path_exe, history, pwsh_server, merge}.rs
  open.rs       — Enter по файлу: классификация, exec в сеансе, shell_open

```

### 1.1 Потоки

На каждый сеанс через `Runtime::spawn_dedicated` (по S0 v2 №7) поднимаются:
- `term-r-<id>` — **reader**. Блокирующий `read` (64 КБ) → пре-сканер OSC → `lock(Vt)` → `processor.advance` (не более 64 КБ под одной блокировкой, `FairMutex::lease`) → unlock. Дальше `dirty.store(true)` и `poke()`, но только при переходе false→true. Семантические события (cwd, A/B/C/D/E, title, exit) отправляются через `MsgSink::send` (редко).
- `term-w-<id>` — **writer**. Канал `WriterCmd { Bytes(Vec<u8>), Resize(PtySize), Close, Kill }`. Записывает в PTY, выполняет resize и закрытие. UI-поток **никогда** не пишет в PTY сам, потому что pipe может быть полон, если ребёнок не читает.
- Выход процесса. Windows — `RegisterWaitForSingleObject` на хэндл процесса (поток из системного пула), колбэк шлёт `Close` во writer. unix — reader получает EIO/0, затем `waitpid`.

Порядок закрытия ConPTY (Windows):
1. Writer вызывает `ClosePseudoConsole`. Никогда не из reader, иначе дедлок.
2. Reader продолжает дренировать conout до EOF.
3. Reader выходит и шлёт `Msg(Exited(code))`.

Если доступен `ReleasePseudoConsole`, он вызывается сразу после spawn: тогда EOF приходит сам по выходу ребёнка.
`Drop` сеанса не блокирует: незавершённое закрытие уходит в detached-поток. При `Core::shutdown(200ms)` все сеансы закрываются параллельно.

Job object (Windows) создаётся без `KILL_ON_JOB_CLOSE` и с `BREAKAWAY_OK`. Он служит для учёта (`ActiveProcesses` → busy-эвристика без интеграции) и для `term.kill` (`TerminateJobObject`). GUI-программы, запущенные из терминала, при выходе Urfin не убиваются.
unix: `setsid` + `TIOCSCTTY`. Busy определяется по `tcgetpgrp(master) != shell_pgid` (точно). kill: `killpg(SIGHUP)`, через 2 с — `SIGKILL`.

### 1.2 Общее состояние сеанса

```rust
pub struct Vt { pub term: Term<VtListener>, pub processor: Processor, pub marks: Marks, pub busy_hint: Option<bool> }
pub struct TermShared {
    pub vt: FairMutex<Vt>,          // alacritty_terminal::sync::FairMutex
    pub dirty: AtomicBool,          // есть непрорисованные изменения
    pub size: AtomicU32,            // cols<<16 | rows
}
```

- `VtListener: EventListener` перехватывает `PtyWrite` (ответы DSR/DA) и отправляет их во writer. `Title` и `ClipboardStore` (OSC 52, по умолчанию `Osc52::OnlyCopy`) уходят Msg в UI. `Bell` визуальный, без звука.
- DEC 2026 (synchronized update): если `processor.sync_timeout()` истёк, UI в кадре под блокировкой вызывает `stop_sync`. Поэтому `Processor` лежит вместе с `Term`.
- Скроллбэк: `term.scrollback = 10000` строк, alacritty растит хранилище лениво. При 120 колонках и 24 Б/ячейку полный буфер весит ≈29 МБ, пока сеанс не выводил много — ≈0. Для фоновых сеансов действует `term.background_scrollback = 2000` (усечение при уходе в фон).

### 1.3 Пре-сканер OSC (`session/scan.rs`)

Байтовый автомат поверх потока до `advance`. Ловит `ESC ] (7|9;9|133|633|1337) ; … (BEL | ESC \)`, длина ограничена 4 КБ (переполнение → отбросить). Последовательность, разрезанная между read-ами, корректна: состояние автомата сохраняется. Чанк режется на части: байты до маркера → `advance`, затем событие с позицией курсора в этот момент, затем остаток. Наши OSC в `Term` не передаются, остальные идут как есть.
События: `PromptStart(A)`, `CommandStart(B)`, `Executed(C)`, `Finished(D, exit)`, `CommandLine(E, text, nonce)`, `Cwd(path, Source{FnCwd|Osc7|Osc9_9|Iterm})`, `Prop(k, v)`.

Доверие:
- `FnCwd` и `E` принимаются только с nonce сеанса.
- OSC 7, 9;9 и 1337 принимаются только у сеансов без нашей интеграции (кастомный shell, ssh).
- Фаза `Prompt` подтверждается, только если между A и B пришёл валидный `FnCwd`, а на unix вдобавок `tcgetpgrp == shell`.
- Nonce — 128 бит, передаётся через env `URFIN_NONCE`. Скрипт удаляет переменную сразу после чтения, чтобы дочерние процессы её не наследовали.

### 1.4 Фазы сеанса и марки

`Phase { Starting, Prompt, Running, Exited(i32), NoIntegration }`:
- `Starting → Prompt` по первому валидному A/B. Если A/B не пришли за 5 с после первого вывода, сеанс переходит в `NoIntegration` с тостом «интеграция недоступна — режим терминала».
- `Prompt → Running` по нашей отправке строки или по C.
- `Running → Prompt` по D+A+B.
- Alt-screen (`TermMode::ALT_SCREEN`) — всегда raw с полноэкранной картинкой.

Марки хранятся как `Line` сетки + снимок `history_size`. Позиции корректируются на дельту истории. После насыщения скроллбэка старые марки отбрасываются. Точная марка нужна только текущему промпту (маскирование, §3.2). Навигация по прошлым блокам — best effort (S6-21).

### 1.5 Снапшот для рендера (egui-free)


Блокировка берётся только на копирование повреждённых строк (`term.damage()` → `reset_damage()`), цвета резолвятся по палитре. Галеи и меши собираются уже без блокировки.

## 2. Рендер в egui (`urfin-ui::term`, владелец S6)

- **Метрики ячейки.** `cw` = advance 'M' моноширинного шрифта, `ch` = row height. Оба округляются до физических пикселей (`pixels_per_point`). При смене ppp или размера шрифта сбрасываются все кэши, `epoch++`.
- **Строка → меш.** Строка разбивается на runs по (fg, flags), фон — отдельными runs. Run обрывается на широком символе (`unicode-width` = 2), на символе без глифа в основном шрифте (fallback, эмодзи) и на процедурных диапазонах. Каждый такой символ ставится отдельно в `col*cw`, так выравнивание сетки не плывёт. Text run: `LayoutJob` без переноса → `Galley` → тесселяция один раз (`epaint::Tessellator`) → `Arc<Mesh>`. Фон — один меш прямоугольников. Кэш: `FxHashMap<(screen_row), RowMesh { hash, mesh }>`. Меш пересобирается при damage или изменении hash. При пересборке атласа egui (сменился `font_image_size`/generation) сбрасывается весь кэш.
- **Процедурные глифы.** U+2500–257F (линии), U+2580–259F (блоки), U+E0B0–E0BF (Powerline-стрелки) рисуются прямоугольниками и путями по сетке ячейки. Получается пиксельная стыковка рамок (mc, Far внутри терминала, htop), и Nerd Font для базовых тем oh-my-posh не нужен.
- **Курсор.** Блок, черта или подчёркивание (DECSCUSR). Мигание по умолчанию выключено (`term.cursor_blink = false`), чтобы в простое было 0% CPU. Если включено — `request_repaint_after(530ms)`, только когда терминал видим и в фокусе.
- **Выделение.** Оверлей полупрозрачными прямоугольниками поверх мешей, без пересборки строк.
- **Бюджеты:**
  - Терминал скрыт панелями → рендер не вызывается, стоимость 0.
  - Видим, без изменений → ≤0,2 мс (копирование `Arc<Mesh>` в список шейпов).
  - Поток вывода (`cat` 100 МБ, 200×60) → полная пересборка ≤4 мс на кадр, repaint не чаще vsync. Reader не ждёт UI и парсит ≥100 МБ/с.
  - Если на Windows-стенде p95 полной пересборки >4 мс, включается план Б: `egui_glow::CallbackFn` с instanced-ячейками и своим атласом за feature `term-gl`.

## 3. Ctrl+O, слои, выделение

### 3.1 Слои окна (контракт с S2, Запрос к S0 №2)
Снизу вверх: **терминал** (вся область между меню и keybar) → **панели** (непрозрачные, `Panel.visible`) → **cmdline** (нижняя строка над keybar) → inline-оверлеи (Alt+F8, автокомплит, prompts) → keybar.
Размер PTY = вся область терминала. Он **не зависит** от видимости панелей и от высоты cmdline. Ctrl+O и Ctrl+F1/F2 не ресайзят PTY, поэтому TUI не перерисовываются. Resize окна дебаунсится 50 мс (ConPTY перерисовывает экран на каждый resize).

### 3.2 Два вида вывода
- **Transcript** (фаза `Prompt`, нет alt-screen). Строки истории и экрана до `A-1` текущего промпта прижаты к низу, прямо над cmdline. Строки самого промпта (`prompt_mask`) маскируются. Cmdline показывает их ячейки (цвета oh-my-posh/starship сохраняются, многострочный промпт — последние ≤3 строки) и сразу за ними — наш редактор. Пустой хвост экрана после `cls` не рисуется: как в Far, строка ввода всегда внизу.
- **Screen** (`Running`, alt-screen, `NoIntegration`). Честный экран PTY во всю область, cmdline скрыт, фокус `Terminal`, ввод raw.

### 3.3 Ctrl+O и автопоказ
- `term.toggle` (Ctrl+O): прячет или показывает обе панели и запоминает прежнее состояние. Фокус остаётся в cmdline.
- При запуске команды из cmdline панели прячутся автоматически, если команда работает дольше `term.auto_show_ms = 300` мс или включила alt-screen. По D панели возвращаются, если `term.return_to_panels = true`. Короткие команды не мигают. Поведение по умолчанию — Решение для владельца №2.

### 3.4 Выделение и буфер обмена
- Мышь: drag — simple, двойной клик — semantic, тройной — line, Alt+drag — block. Если приложение включило mouse mode, события уходят в PTY (SGR-кодирование), а Shift+мышь всегда выделяет.
- Копирование: `term.copy` (Ctrl+Shift+C, Ctrl+Ins). В raw Ctrl+C при активном выделении копирует и снимает выделение, без выделения шлёт `^C` в PTY.
- Вставка: `term.paste` (Ctrl+Shift+V, Shift+Ins). Если включён `BRACKETED_PASTE`, текст оборачивается в `ESC[200~…ESC[201~`. Многострочная вставка в shell без bracketed paste (cmd) требует inline-подтверждения одной строкой.
- Буфер обмена — через `egui::Context::copy_text`. OSC 52: только запись, чтение запрещено.
- Скролл: колесо, `term.scroll {lines|pages}` (Shift+PgUp/PgDn). В alt-screen с `ALTERNATE_SCROLL` колесо превращается в стрелки.

### 3.5 Кодировщик ввода (`vt/input.rs`)
egui `Key` + модификаторы → байты xterm: стрелки и Home/End в normal и APP_CURSOR, F1–F12 с модификаторами (`CSI 1;m X`, `CSI n;m ~`), Alt → ESC-префикс, Ctrl+буква → C0. Отдельно: AltGr на Windows (Ctrl+Alt+символ → символ, если egui отдал `Text`), focus in/out (`CSI I/O` при `FOCUS_IN_OUT`), мышь SGR/normal. Kitty keyboard — когда приложение включает протокол (alacritty ведёт режим). Табличные тесты против эталонов xterm.
Win32-input-mode (`CSI ?9001h` от ConPTY) — отдельная задача S6-20. Она даёт полную точность клавиш консольным Win32-программам (Far внутри терминала, Ctrl+Space и т.п.).

## 4. Shells

### 4.1 Обнаружение (`shells/discover.rs`, Lane::Interactive, после первого кадра, кэш в `state_dir/term/shells.toml`)

| id | Windows | macOS / Linux |
|---|---|---|
| `cmd` | `%ComSpec%` | — |

### 4.2 Сеансы и переключение
- `term.shell {id}` делает сеанс shell активным; если сеанса нет, он запускается в cwd активного таба (локальный путь или ближайший локальный предок).
- Буфер cmdline при переключении сохраняется. У сеанса, ставшего активным, срабатывает ленивая синхронизация cwd.
- Меню shell (`term.shell_menu`) — inline-список над cmdline: shell, состояние, cwd.
- Выход shell (`exit`) не закрывает Urfin. В транскрипт пишется строка `[процесс завершён, код N]`, сеанс перезапускается при следующей команде.
- `Handler::on_quit` (S0 v2 №13): если есть сеансы в `Running` или с busy=true, возвращается `Veto` с вопросом «Завершить N процессов?».
- Env ребёнка:
  - всегда: `TERM_PROGRAM=Urfin`, `TERM_PROGRAM_VERSION`, `COLORTERM=truecolor`, `URFIN_SESSION`, `URFIN_NONCE`;
  - unix: `TERM=xterm-256color`; на macOS `LANG=<locale>.UTF-8`, если не задан (запуск из Finder идёт без LANG);
  - zsh/bash на macOS запускаются как login (`-l`), как в Terminal.app.

## 5. Shell integration

Скрипты вшиты (`include_str!`) и при первом использовании атомарно пишутся в `state_dir/term/shell/<ver>/`. Протокол общий: в каждом промпте `633;D;<exit>` → `633;A` → `633;P;FnCwd=<nonce>;<path>` → промпт пользователя → `633;B`. Перед выполнением `633;C`, где shell это умеет. Для истории — `633;E;<cmdline>;<nonce>`. В posix-путях percent-кодируются байты <0x20, `%` и `;`.

| shell | инъекция | cwd | C (preexec) | E (cmdline) | тихие хуки |
|---|---|---|---|---|---|
| pwsh 7 / powershell 5.1 | `-NoLogo -NoExit -EncodedCommand <b64 UTF-16LE>` (профиль грузится до; ExecutionPolicy/AllSigned не мешают) | обёртка над `prompt` после профиля (совместима с oh-my-posh/starship); 5.1 — `[char]27` вместо `` `e`` | неявно (мы отправили строку); в raw — нет | в `prompt`: `(Get-History -Count 1).CommandLine`, если Id новый | PSReadLine `Set-PSReadLineKeyHandler -Chord Ctrl+Alt+Shift+F12` → `Set-Location -LiteralPath (файл)`; `InvokePrompt()`. `Ctrl+Alt+Shift+F11` → `RevertLine()` |
| cmd | env `PROMPT=$e]633;D$e\$e]633;A$e\$e]633;P;FnCwd=<nonce>;$P$e\<PROMPT пользователя или $P$G>$e]633;B$e\` | `$P` | неявно | нет (raw-ввод в историю не попадает) | нет → видимый `cd /d "X"` перед командой; UNC → `pushd "\\s\sh\x"` |
| bash (≥3.2; Git Bash) | `bash --rcfile <dir>/urfin.bash -i` (rcfile подключает `/etc/bash.bashrc`, `~/.bashrc`; login — `/etc/profile`, `~/.bash_profile`) | `PROMPT_COMMAND` (prepend) | `PS0` (bash ≥4.4) | `history 1` в PROMPT_COMMAND | `bind -x '"\e[24;8~": __fn_cd'`, `bind -x '"\e[23;8~": __fn_clear'` |
| zsh | `ZDOTDIR=<dir>/zsh`, наши `.zshenv/.zprofile/.zshrc/.zlogin` восстанавливают `ZDOTDIR` пользователя (`URFIN_USER_ZDOTDIR` или `$HOME`) и source-ят его файлы | `precmd` (add-zsh-hook) | `preexec` | `preexec $1` | `zle -N` + `bindkey '^[[24;8~'` (cd + `zle reset-prompt`) |
| fish | `fish --init-command 'source <dir>/urfin.fish'` | `fish_prompt` event | `fish_preexec` | `$argv` | `bind \e\[24\;8~ …; commandline -f repaint` |

Путь к скриптам — env `URFIN_SHELL_DIR` + `WSLENV=URFIN_SHELL_DIR/p:URFIN_NONCE:URFIN_SESSION` (WSL сам транслирует путь). Скрипт один раз сообщает `633;P;FnMountRoot=/mnt/` | как у shell | как у shell | как у shell | как у shell |

- Payload тихого cd — файл `state_dir/term/run/<session>/cwd` (UTF-8, атомарная запись). Затем во writer отправляется аккорд `CSI 24;8~`, то есть Ctrl+Alt+Shift+F12. ConPTY переводит его в KEY_EVENT, PSReadLine и readline ловят его как привязку, эха нет. Для WSL цепочка ConPTY → wsl.exe → VT проверяется тестом S6-13.
- Clink. Если `AutoRun` содержит clink, мы его не трогаем. Если Clink перетёр `PROMPT` и маркеров нет, сеанс уходит в `NoIntegration`. Отдельный clink-скрипт оценим позже (S6-21).
- Constrained Language Mode (корпоративный AppLocker). Если `InvokePrompt` или чтение файла запрещены, хук сообщает `633;P;FnHook=0`, и мы переходим на видимый `Set-Location -LiteralPath`.
- `term.shells[*].integration = false` или `[term] integration = false` отключают инъекцию (Решение для владельца №4).

### 5.1 Синхронизация cwd
- **shell → панель.** Пришёл `Cwd(p)` от доверенного источника, и он отличается от `active_tab().loc`. Если это не эхо нашего же тихого cd (сравнение с `pending_sync`), отправляется `panel.go path=p` на активную сторону (`CommandSender`, `Origin::Internal`). Если таб на нелокальной локации (архив, sftp), панель всё равно уходит на p.
- **панель → shell, лениво.** Помечаем `want_cwd = loc`, если loc локальный. Синхронизация выполняется перед submit, при `term.toggle` и при входе в raw. Нелокальный таб → ближайший локальный предок (`Location.outer`), в статусе значок «cwd не совпадает».
- **Маппинг путей.**
  - WSL: `/mnt/<d>/x` ↔ `D:\x`, остальное ↔ `\\wsl.localhost\<D>\x`.
  - Путь другого дистрибутива или сетевой путь, не отображаемый в shell, — без синхронизации, тост.
  - Git Bash: `/c/x` ↔ `C:\x`.
- Режим: `term.sync_cwd = "both" | "shell_to_panel" | "panel_to_shell" | "off"`, по умолчанию `both`.

## 6. Строка ввода (cmdline)

`LineEditor` (в `TermState`): буфер, курсор, выделение, undo/redo (группировка по словам), перемещение по словам с учётом кавычек. Вся правка идёт командами `cmdline.*` (S3 маппит). Печатный текст при `Focus::Panel` или `Cmdline` превращается в `cmdline.insert {text}` (поведение Far).

Submit (`cmdline.submit`, Enter на непустой строке):
1. Ленивая синхронизация cwd (§5.1).
2. Если PTY-строка «грязная» (в raw набирали текст), отправляется хук clear-line; для cmd — `ESC`.
3. Отправляется `текст\r`. Для многострочного текста, если включён `BRACKETED_PASTE`, — `ESC[200~…ESC[201~\r`.
4. История `push`, фаза `Running`, запускается таймер автопоказа (§3.3).

Пустой Enter при фокусе на панели передаётся в `panel.enter`.
`Shift+Enter` выполняет команду в новом окне ОС (`start`/`open -a Terminal`) — позже.

### 6.1 История
- Хранится по shell-ключу (`pwsh`, `cmd`, `wsl:Ubuntu`, …) в `state_dir/term/history/<key>.jsonl`. Формат: `{"t":unix,"cmd":"…","cwd":"…","exit":0,"lock":false}`. Запись — append на `Lane::Bulk`, при загрузке выполняется компакция, если записей больше 2×cap.
- Дедуп: повтор переносится в конец, старая запись удаляется. `term.history.max = 5000`.
- Источники: команды из cmdline и `E` из raw (с nonce). Не сохраняются команды с ведущим пробелом (`ignore_space = true`) и совпадающие с `exclude` (маски, например `*password*`, `*token*`, `*secret*`).
- Импорт нативных историй, только чтение и с пометкой: PSReadLine `ConsoleHost_history.txt`, `~/.bash_history`, `~/.zsh_history` (extended-формат), fish `fish_history`. Флаг `import_native` (Решение для владельца №5).
- **Alt+F8** — inline-оверлей над cmdline с фильтром по мере набора (подстрока, затем fuzzy). Enter вставляет, Shift+Enter выполняет, Del удаляет, Ins закрепляет (lock, не вытесняется), Ctrl+R переключает «этот shell / все shells».
- Ctrl+E/Ctrl+X (Far) и ↑/↓ при пустой строке — `cmdline.history.prev/next` с префиксным поиском по уже введённому.

### 6.2 Автокомплит
Что реально:
- **Пути.** Относительно cwd сеанса. `std::fs::read_dir` на `Lane::Interactive`, кэш последнего каталога. Для WSL — через `\\wsl.localhost\…`. Регистр игнорируется на Windows и macOS. Кавычки по `PathStyle` (§6.3).
- **Команды из PATH.** Скан PATH + PATHEXT (Windows) или exec-бит (unix) при старте сеанса, кэш по mtime каталогов. Для WSL не сканируем.
- **История** — префикс и frecency.
- **pwsh native** — фоновый `pwsh -NoLogo -NoProfile -NonInteractive -Command -` (протокол — JSON-строки). Он делает `Set-Location <cwd>` и `TabExpansion2 -inputScript $s -cursorColumn $c`. Запускается лениво при первом Tab в pwsh-сеансе, убивается после 10 мин простоя. Таймаут ответа — `complete.timeout_ms = 300`, опоздавший ответ отбрасывается. Даёт cmdlet-ы, параметры, модули (autoload), пути и типы. **Не видит** переменные и функции интерактивного сеанса. В CLM или при ошибке старта отключается до перезапуска.
- **zsh/bash/fish native** — handoff: `cmdline.complete_native` (по умолчанию Shift+Tab) кладёт буфер в PTY-строку, переводит сеанс в raw и шлёт `\t`. Дальше работает родной комплит shell, Enter выполняет, а строка попадает в историю через `E`. Для pwsh то же самое даёт PSReadLine MenuComplete. Захват комплита zsh через zpty и fish `complete -C` в фоне — позже, если будет спрос.
- UI: ghost-текст из истории (`complete.ghost = true`, → или End принимает). Tab открывает inline-popup над cmdline (до 12 строк), источники сливаются: native > пути > PATH > история, дедуп. Повторный Tab — следующий вариант.

### 6.3 Вставка имён (Far)

| команда | клавиша (пресет Far) | что вставляет |
|---|---|---|
| `cmdline.insert_name {side=active}` | Ctrl+Enter | имя под курсором |
| `cmdline.insert_name {side=passive}` | Ctrl+Shift+Enter | имя под курсором в пассивной панели |
| `cmdline.insert_name {full=true}` | Ctrl+F | полный путь файла под курсором |
| `cmdline.insert_path {side=left|right}` | Ctrl+[ / Ctrl+] | путь каталога левой/правой панели |
| `cmdline.insert_name {side=left|right, full=true}` | Ctrl+Shift+[ / ] | полный путь файла под курсором слева/справа |
| `cmdline.insert_selection` | (не назначено) | все выделенные имена через пробел |

- Квотирование по активному shell (`shells/quote.rs`):
  - cmd: `"…"` при пробелах и `&()[]{}^=;!'+,~`;
  - pwsh: `'…'` с удвоением `'`;
  - posix: `'…'` с `'\''`;
  - WSL и Git Bash: путь сначала мапится.
- Вставка в позицию курсора, пробел-разделитель ставится автоматически. На `..` вставляется путь каталога.
- Нелокальная локация — тост «нет локального пути».

## 7. Enter по файлу

Цепочка разрешения задаётся S0 (Запрос №3). S6 реализует последнее звено — `term.open {path, verb?}`:
1. **Классификация** (Lane::Interactive, ≤1 КБ чтения):
   - Windows: расширение из PATHEXT (`.exe .com .bat .cmd .ps1`…), для PE — поле Subsystem (GUI или console).
   - unix: exec-бит + `#!` или Mach-O/ELF.
2. **Консольная программа или скрипт** — выполняется **в активном сеансе** в синтаксисе shell: pwsh `& '.\x.exe'`, cmd `"x.exe"`, posix `./x`. `.ps1` — в pwsh-сеансе, иначе `pwsh -File`. `.bat`/`.cmd` в pwsh напрямую. cwd = каталог панели (через ленивую синхронизацию). Транскрипт и автопоказ — как у обычной команды.
3. **GUI-exe и остальные файлы** — ассоциация ОС, в фоне, без ожидания:
   - Windows: `ShellExecuteExW` (verb по умолчанию NULL, `SEE_MASK_NOASYNC`, `lpDirectory` = каталог) на коротком `spawn_dedicated`-потоке с `CoInitializeEx(APARTMENTTHREADED | DISABLE_OLE1DDE)`. Поток живёт ровно один вызов, поэтому зависание сетевого пути не трогает пулы. Нет ассоциации → окно ОС «Открыть с помощью» (это UI ОС, не наш модал).
   - macOS: `open <path>`; Linux: `xdg-open` (fallback `gio open`). Оба через `std::process::Command` с `setsid`, детач.
   - Ошибки возвращаются Msg → тост.
4. **Варианты:**
   - Shift+Enter (`verb=new_window`) — exe в новом консольном окне ОС через `ShellExecuteExW`;
   - `term.open {verb=runas}` — от администратора;
   - `verb=openas` — диалог «Открыть с помощью».

## 10. Задачи для Claude Code

Общее для всех задач: unsafe только в `term/src/sys`. Интеграционные тесты на реальных shell идут в CI: windows-latest (cmd, powershell 5.1, pwsh 7), ubuntu (bash; zsh и fish через apt), macos (zsh, bash 3.2).

**S6-01 Каркас term**
- Цель: модули по §1, `TermState` в `AppState.ext`, `TermHandler` (ns `term`, `cmdline`, команды-заглушки с `CommandMeta`), `[term]` через `config.section`, ключи Fluent `cmd-term-*` и `cmd-cmdline-*`.
- Крейт: term.
- Приёмка: `CommandRegistry` видит все команды §9, `validate` проходит, clippy чист.
- Тест: unit на конфиг (insta-снапшот дефолтов).
- Зависит: S1-07, S1-10.

**S6-02 ConPTY**
- Цель: `sys::conpty`:
  - `spawn(SpawnSpec, PtySize) -> PtyParts { reader, writer, control, exit }`;
  - sideload `conpty.dll` и fallback;
  - `ReleasePseudoConsole` через `GetProcAddress`;
  - job object (`busy()` по `ActiveProcesses`, `kill_tree`);
  - порядок закрытия §1.1, `RegisterWaitForSingleObject`;
  - env-блок `CREATE_UNICODE_ENVIRONMENT`, экранирование аргументов по правилам CRT, `STARTF_USESTDHANDLES` без наследования хэндлов.
- Крейт: term (sys).
- Приёмка:
  - `cmd /c echo hi` даёт `hi` и код 0;
  - 100 циклов spawn/close без зависаний (каждый ≤1 с) и утечек хэндлов (GetProcessHandleCount);
  - close при непрочитанном conout не виснет;
  - kill убивает дерево (`cmd /c ping -t`);
  - с bundled и с system ConPTY.
- Тест: интеграционный, Windows-only.
- Зависит: 01.

**S6-03 unix PTY**
- Цель: `sys::unix`: openpty (rustix-openpty), `setsid`, `TIOCSCTTY`, `TIOCSWINSZ`, `busy()` через `tcgetpgrp`, `kill_tree` (SIGHUP → SIGKILL через 2 с), неблокирующий Drop.
- Крейт: term (sys).
- Приёмка: как в S6-02 на macOS и Linux; `sleep 100` даёт busy=true, после выхода — false.
- Тест: интеграционный.
- Зависит: 01.

**S6-04 Pipeline сеанса**
- Цель: reader/writer-потоки (`spawn_dedicated`), `TermShared` (FairMutex<Vt>), `VtListener` (PtyWrite → writer), пре-сканер OSC §1.3 (разрывы между read-ами, лимит 4 КБ), события → Msg, `poke` с коалесцированием, DEC 2026 stop_sync по таймауту, резолв `Exited`.
- Крейт: term.
- Приёмка:
  - fuzz/proptest: любое разбиение потока на чанки даёт те же события и ту же сетку, что цельный поток;
  - 100 МБ `yes`-подобного вывода парсятся ≥100 МБ/с (release);
  - в простое 0% CPU;
  - число `poke` ≤ числа кадров.
- Тест: unit (сканер), интеграционный с фейковым PTY (pipe), criterion.
- Зависит: 02, 03, Запрос S0 №1.

**S6-05 Кодировщик ввода**
- Цель: `vt/input.rs` по §3.5 (клавиши, APP_CURSOR, модификаторы, AltGr, мышь SGR/normal, focus, bracketed paste).
- Крейт: term.
- Приёмка: таблица ≥150 эталонов xterm проходит; vim и htop в Linux-сеансе управляются стрелками, F-клавишами и мышью (ручной чек-лист).
- Тест: табличный unit.
- Зависит: 01.

**S6-06 Рендер сетки**
- Цель: `GridSnapshot` (term) + виджет `urfin-ui::term::GridView` по §2: метрики, мешы строк, кэш по damage и hash, фоны runs, wide и fallback, процедурные U+2500–259F и E0B0–E0BF, курсор, оверлей выделения, сброс кэша при ppp или атласе.
- Крейт: term, ui.
- Приёмка:
  - скриншот-тесты (egui_kittest или ручной чек-лист) для рамок mc/Far, кириллицы, CJK, эмодзи, 256 цветов и truecolor;
  - бюджеты §2 на Windows-стенде (замеры в PR).
- Тест: criterion `snapshot+build 200×60 full` и `idle`.
- Зависит: 04, Запросы S0 №2 и №4.

**S6-07 Выделение, буфер, скролл**
- Цель: §3.4.
- Крейт: term, ui.
- Приёмка:
  - semantic, line и block работают;
  - Ctrl+C копирует при наличии выделения, иначе шлёт `^C`;
  - bracketed paste в bash;

## 11. Запросы к S0

1. **Пробуждение UI без Msg.** Нужен `MsgSink::poke()` (или `Runtime::waker()`), то есть коалесцированный `wake()` без аллокации Msg. Терминальный поток будит кадр до 60 раз/с, данные UI читает из `TermShared`. Альтернатива — пустой Msg через bounded-канал: лишние аллокации и бэкпрешер на выводе.
2. **Слои окна и владение модулем.** Модуль `urfin-ui::term` (GridView, cmdline-виджет, оверлеи Alt+F8 и комплита) принадлежит S6. Контракт с S2 по §3.1:
   - порядок слоёв;
   - `term_area` = окно минус меню и keybar;
   - панели непрозрачны и не меняют размер PTY;
   - cmdline — нижняя строка переменной высоты 1–3;
   - S2 передаёт шрифт и метрики.
3. **Цепочка Enter по файлу.** `panel.enter` (файл) → `file.open`. Кто владеет `file.open` и в каком порядке опрашиваются резолверы? Предложение: [S8 архивы/контейнеры] → [пользовательские ассоциации по маскам, Far F9] → [S6 `term.open`: исполняемые в сеансе, остальное — ОС].
4. **Моноширинный шрифт.** Один вшитый моно-шрифт для панелей и терминала (предлагаю Cascadia Mono, OFL, кириллица и box-drawing), его id в egui, `ui.font_mono_size`. Пользовательский файл шрифта — `ui.font_mono_file`. Box-drawing, блоки и Powerline S6 рисует сам.
5. **Фокус и сырой ввод (S1 + S3).**
   - В `Focus::Terminal` S3 применяет только биндинги с контекстом `terminal` или `global` (Ctrl+O, переключение shell и т.п.). Остальные нажатия уходят командами `term.key {key, mods}` / `term.input {text}`.
   - В `Focus::Panel` печатный текст без биндинга уходит в `cmdline.insert {text}`.
   - Нужно зафиксировать имена клавиш (строки egui `Key::name()`).
6. **Зависимости и deny.toml.** Одобрить `alacritty_terminal =0.26.0` (Apache-2.0), `rustix 1.1`, `rustix-openpty 0.2`, `base64 0.22`, `unicode-width 0.2`. alacritty_terminal безусловно тянет свой tty-слой (`windows-sys 0.59`, miow, piper, polling, signal-hook), поэтому дубль windows-sys 0.59/0.61 нужно внести в `skip` deny.toml. LTO вырезает неиспользуемое, на бинарь влияние мало (контроль в S6-22).

## 12. Решения для владельца

1. **Shell по умолчанию на Windows.** Определяет, что открывается за панелями при первом запуске и как быстро он готов.
   - Варианты:
     - (а) cmd — как в DN/Far, старт ≈30 мс, ≈5 МБ, но слабый язык и нет кодов выхода в промпте;
     - (б) pwsh 7, если установлен, иначе cmd — современный shell, полный комплит и коды выхода, старт 300–600 мс (прогрев скрывает), 60–100 МБ;
     - (в) Windows PowerShell 5.1 — есть всегда, но медленный старт и старый PSReadLine.
   - Рекомендация: **(б)**, `default_shell = "auto"`, при первом старте inline-подсказка, как сменить.
2. **Где показывать вывод команд.**
   - Варианты:
     - (а) как в Far: вывод за панелями, Ctrl+O; при долгой команде (>300 мс) панели прячутся сами и возвращаются по завершении;
     - (б) отдельная зона снизу (сплит, регулируемая высота), панели всегда видны;
     - (в) (а) по умолчанию + (б) опцией `term.layout = "behind" | "split"`.
   - Рекомендация: **(в)**. Архитектура одинаковая (слой терминала), разница — только в раскладке S2.
3. **Поставлять ли свой ConPTY (conpty.dll + OpenConsole.exe, MIT, ≈2–3 МБ) рядом с exe.**
   - Варианты:
     - (а) да, с fallback на системный — одинаковое поведение на Win10/11, правильный порядок OSC (границы промпта), быстрее; дистрибутив из 3 файлов (exe остаётся <15 МБ);
     - (б) только системный — один файл; на старых сборках Windows возможны «съехавшие» промпты и артефакты resize.
   - Рекомендация: **(а)**. В portable-zip и в установщике файлы лежат рядом с exe, `term.conpty = "auto"`.
4. **Автоматическая инъекция shell integration.** Без неё нет синхронизации cwd, своей строки ввода и истории из raw.
   - Варианты:
     - (а) автоматически, без правки файлов пользователя (аргументы и env при запуске), выключатель на shell;
     - (б) только по явному включению;
     - (в) инструкция «добавьте строку в профиль».
   - Рекомендация: **(а)**. Скрипты открыты в `state_dir`, nonce защищает от подмены, CLM и AllSigned поддерживаются.
5. **История команд на диске.** История может содержать секреты.
   - Варианты:
     - (а) сохранять по shell, с исключениями (ведущий пробел, маски `*password*/*token*/*secret*`), импортировать нативные истории только на чтение;
     - (б) сохранять без импорта нативных;
     - (в) хранить только в памяти сессии.
   - Рекомендация: **(а)**, маски редактируются в `[term.history]`, файлы лежат в профиле пользователя (ACL профиля).
