# S4 — VFS и листинг: спецификация

Статус: draft v1 (2026-10-14). Владелец: S4. Опирается на контракты `urfin-core` (specs/S1.md). Изменения core перечислены в «Запросах к S0».
Проверенные версии крейтов на 2026-10-14: windows-sys 0.61.2, rustix 1.1.5, notify 8.2.0, compact_str 0.10.

---

## 0. Ключевые решения

- **Решение:** адресом служит `core::Location`, отдельного `VfsPath` нет (`pub type VfsPath = Location`). Backend выбирается через `VfsRegistry` по `Location::backend`.
  **Почему:** один адрес на всё приложение, S8 добавляет `zip`/`sftp` регистрацией без новых типов.
- **Решение:** листинг устроен как pull-стрим `ListStream::next_batch(&mut Vec<Entry>)`, один вызов соответствует одному системному буферу. Нарезку на чанки для core (первый сразу, дальше ≥2048 записей или раз в 8 мс) делает общий `Batcher`, а не backend.
  **Почему:** backend остаётся простым (цикл «syscall → декодирование»), политика стриминга одна для всех ОС и для S8, повторное использование `Vec` обходится без аллокаций.
- **Решение:** на Windows основной путь — `NtQueryDirectoryFile` с `FileFullDirectoryInformation` и буфером 32 КБ на первый вызов, 512 КБ на последующие. Fallback: `FindFirstFileExW(FindExInfoBasic, FIND_FIRST_EX_LARGE_FETCH)`, затем `std::fs::read_dir`.
  **Почему:** нет копирования в `WIN32_FIND_DATAW` (592 байта на запись), syscall'ов в 8–16 раз меньше (на SMB это round-trip'ы), а поле `EaSize` содержит reparse-тег, так что тип ссылки определяется без дополнительных вызовов. Маленький первый буфер даёт первые строки меньше чем за 1 мс. `NtQueryDirectoryFileEx` (Win10 1709+) ничего нужного не добавляет.
- **Решение:** на macOS используется `getattrlistbulk` (буфер 256 КБ), на Linux — `getdents64` через `rustix::fs::RawDir` и `statx`. На Linux `statx` распараллеливается scoped-потоками, если в каталоге больше 8k записей.
  **Почему:** это самые быстрые штатные API. На Linux метаданные требуют syscall на каждый файл, поэтому их распараллеливание даёт прирост в 3–4 раза.
- **Решение:** имена в `Entry.name` (`CompactString`, inline до 24 байт) хранятся без арены. Для сортировки и фильтра S4 строит SoA-массив `SortRec` (24 байта: группа, 8-байтный сложенный префикс, aux, idx), а во время загрузки ещё и `NameArena` (один `Vec<u8>` и смещения).
  **Почему:** около 90% имён ≤24 байт и не аллоцируются. Сравнение по префиксу решает большинство случаев без чтения строк, массив плотный и дружелюбен к кэшу. Контракт `Entry` из core не меняется.
- **Решение:** natural sort реализован собственным компаратором: регистронезависимый, ASCII-fast-path, цифровые группы сравниваются по значению, `ё` идёт сразу после `е`. Сортировка параллельная (`par_sort_unstable_by`) при n ≥ 16k. Во время стриминга порядок пересчитывается геометрически (на 2k, 4k, 8k… и на `Done`).
  **Почему:** ICU-коллация тяжёлая и медленная. Геометрический пересорт стоит O(n log n) суммарно, при этом верх списка перестраивается лишь несколько раз, а не на каждый чанк.
- **Решение:** watcher на Windows свой: `ReadDirectoryChangesExW` с `ReadDirectoryNotifyExtendedInformation`, IOCP и один поток. На macOS и Linux используется `notify` 8.2 (FSEvents/inotify). При ошибке backend'а (некоторые сетевые ФС) включается polling. Наблюдаются только каталоги видимых табов, без рекурсии.
  **Почему:** extended-события сразу несут размер, время и атрибуты, поэтому инкрементальный патч не делает лишних stat. Наблюдение только видимых табов не держит handle на фоновых каталогах (на Windows открытый handle мешает переименовать родителя). Писать свои FSEvents ради выигрыша на второй ОС невыгодно.
- **Решение:** обновление после событий зависит от размера каталога. До 5000 записей, а также при overflow или шторме выполняется полный `panel.refresh` (double-buffer core). В больших каталогах применяется инкрементальный `Patch` с семантикой `swap_remove` (нужен S0). Кэш каталогов работает по принципу stale-while-revalidate (LRU 16 каталогов / 200k записей). Если кэшированный каталог всё время был под наблюдением и событий не было, он отдаётся без I/O.
  **Почему:** полный перечитанный листинг всегда корректен и в маленьких каталогах дешевле любых диффов. Патч нужен только там, где rescan 100k+ записей на каждое событие съест CPU.
- **Решение:** на Windows внутренние вызовы всегда используют verbatim-пути (`\\?\C:\…`, `\\?\UNC\srv\share\…`). Конвертация идёт в стековый `SmallVec<[u16; 264]>`. В `Location` хранится обычная форма.
  **Почему:** нет лимита MAX_PATH, не нужен манифест `longPathAware`, доступны имена с хвостовыми точками и пробелами. Конвертация обходится без аллокаций.
- **Решение:** имена, не представимые в UTF-8 (непарные суррогаты на NTFS, произвольные байты на Linux), кодируются обратимо: каждый невалидный юнит заменяется символом из приватной зоны U+10F700…U+10FFFF, а записи ставится флаг `Attrs::ESCAPED_NAME` (нужен S0). Декодирование делает `vfs::name::to_os()`.
  **Почему:** `Entry.name` остаётся `str`, отображение и сортировка работают, операции S5 получают точное исходное имя. Нормальные имена никаких расходов не несут.

    #[error("not found: {0}")] NotFound(PathBuf),

    #[error("not a directory: {0}")] NotDir(PathBuf),
    #[error("unsupported: {0}")] Unsupported(&'static str),
    #[error("cancelled")] Cancelled,

    /// Оценка числа записей, если ФС её знает (иначе None).

    pub attrs: Attrs,

    pub alloc_size: Option<u64>,

    pub nlink: Option<u32>,

pub struct Space { pub total: u64, pub free: u64, pub avail: u64 }

    fn scheme(&self) -> &'static str;                         // "local"
    fn caps(&self, at: &VfsPath) -> Caps;
    fn list(&self, dir: &VfsPath, opts: &ListOpts) -> Result<Box<dyn ListStream>, VfsError>;

pub struct VfsRegistry { /* FxHashMap<&'static str, Arc<dyn Vfs>> */ }

### 2.2 Стриминг в core

`VfsListing` реализует `core::ListingService`.

- `load(req)` порождает `rt.spawn(Lane::Interactive, "vfs.list", req.cancel, …)`. В задаче:
  1. `DirCache` hit, fresh: отправить `Chunk` (все записи и visible) и `Done`, I/O нет. Hit, stale: отправить кэш и `Done`, затем `cx.dispatch(panel.refresh{tab})`.
  2. Иначе открыть `ListStream`, в цикле `next_batch` → `Batcher`.
  3. `Batcher` отправляет первый чанк сразу после первого батча и сортирует его внутри себя. Дальше копит до ≥2048 записей или 8 мс.
  4. Каждый чанк уходит как `Chunk { entries, visible }` (запрос к S0 №1): `visible` — индексы новых записей, прошедших hidden и фильтр, в порядке прихода. Core дописывает их в `order` через `Arc::make_mut`.
  5. Параллельно ведётся `SortRec` + `NameArena`. Когда `len` достигает 2k·2^k, на cpu-pool запускается полная сортировка, результат идёт как `Order { order, for_len, seq }`. Пока она идёт, новые чанки продолжают приходить и дописываются в хвост порядка.
  6. На конце потока: финальный `Order` (если сортировка не `Unsorted`), затем `Done`. Ошибка → `Failed`. Отмена → тихий выход, `MsgSink::send` с cancel.
- `arrange(req)` порождает `spawn_cpu("vfs.arrange")`: строит `SortRec` из `req.entries` (par при n ≥ 32k), фильтрует, сортирует и отправляет `Order { seq }`.
- Отправка сообщений только через `listing_msg(tab, gen, …)`.

```rust
pub struct VfsListing { reg: Arc<VfsRegistry>, cache: Arc<DirCache>, hub: WatchHub, cfg: VfsCfg }
impl VfsListing { pub fn new(reg: Arc<VfsRegistry>, cfg: VfsCfg, sender: CommandSender, rt: &Runtime) -> Self; }
impl ListingService for VfsListing { fn load(..); fn arrange(..); fn tab_event(..) /* запрос №4 */ }

#[derive(Clone, Debug, Deserialize)] #[serde(default)]
pub struct VfsCfg {                 // секция [vfs]
    pub cache_dirs: u16,            // 16
    pub cache_entries: u32,         // 200_000
    pub patch_threshold: u32,       // 5000 — меньше → полный refresh
    pub debounce_ms: u16,           // 50
    pub max_latency_ms: u16,        // 250
    pub poll_interval_ms: u32,      // 2000 (минимум; адаптивно ×10 от времени листинга)
    pub dotfiles_hidden_on_windows: bool, // false (решение владельца №3)
    pub natural_sort: bool,         // true (решение владельца №5)
    pub dir_size_threads: u8,       // 0 = авто: 4 SSD / 1 HDD|сеть
}
```

## 3. Platform fast paths

### 3.1 Windows (приоритет)

**Открытие каталога:** `CreateFileW(verbatim, FILE_LIST_DIRECTORY | SYNCHRONIZE, FILE_SHARE_READ|WRITE|DELETE, null, OPEN_EXISTING, FILE_FLAG_BACKUP_SEMANTICS, 0)`.

**Чтение:** `NtQueryDirectoryFile(h, 0, None, null, &iosb, buf, len, FileFullDirectoryInformation /*2*/, ReturnSingleEntry=FALSE, FileName=null, RestartScan=TRUE на первом вызове)`.
- Буфер: 32 КБ на первый вызов (≈300 записей, первые строки), затем 512 КБ, выровнен по 8.
- Конец каталога — `STATUS_NO_MORE_FILES`. При `STATUS_INVALID_INFO_CLASS` / `STATUS_NOT_IMPLEMENTED` / `STATUS_INVALID_PARAMETER` (сторонние ФС, часть редиректоров) включается fallback.
- `STATUS_PENDING` невозможен: handle без OVERLAPPED.

Разбор `FILE_FULL_DIR_INFORMATION` (цепочка по `NextEntryOffset`):

| поле | → |
|---|---|
| `FileName` (`FileNameLength` байт, UTF-16) | `name`: ASCII-fast-path, затем `CompactString::from_utf16`, при ошибке экранирование. `.` и `..` пропускаются |
| `EndOfFile` | `size` (у каталогов 0) |
| `LastWriteTime` | `mtime = (t − 116444736000000000) × 100` |
| `FileAttributes` | `HIDDEN`, `SYSTEM`, `READONLY`, `ARCHIVE`, `COMPRESSED`, `ENCRYPTED`, `REPARSE`. `OFFLINE` выставляется для `OFFLINE`, `RECALL_ON_OPEN` и `RECALL_ON_DATA_ACCESS` |
| `EaSize` при `REPARSE_POINT` | reparse-тег, без доп. вызовов |

Тип записи по тегу:
- `IO_REPARSE_TAG_SYMLINK`, `IO_REPARSE_TAG_MOUNT_POINT` (junction и точки монтирования томов): `LinkDir` при `FILE_ATTRIBUTE_DIRECTORY`, иначе `LinkFile`.
- `IO_REPARSE_TAG_APPEXECLINK`: `LinkFile`.
- `IO_REPARSE_TAG_CLOUD*`, `DEDUP`, `WOF` и прочие: обычные `File`/`Dir` (это не ссылки). Такие файлы никогда не открываются в листинге, чтобы не запустить скачивание OneDrive.
- `LinkBroken` в листинге не определяется (цель на сети/диске может отвечать секунды). Его выдаёт только `stat`.

**Fallback:** `FindFirstFileExW(verbatim\*, FindExInfoBasic, …, FindExSearchNameMatch, null, FIND_FIRST_EX_LARGE_FETCH)` и `FindNextFileW`. Тег берётся из `dwReserved0`. Последний рубеж — `std::fs::read_dir` (`std_fs.rs`, он же эталон в тестах).

**stat / stat_entry:**
- `stat`: `CreateFileW(…, FILE_READ_ATTRIBUTES, share all, FILE_FLAG_BACKUP_SEMANTICS | (follow ? 0 : FILE_FLAG_OPEN_REPARSE_POINT))`, затем `GetFileInformationByHandleEx(FileBasicInfo, FileStandardInfo, FileIdInfo, FileAttributeTagInfo)`.
- Цель ссылки — `DeviceIoControl(FSCTL_GET_REPARSE_POINT)`.
- `stat_entry`: `FindFirstFileExW` по точному имени (одна запись вместе с тегом).

**space:** `GetDiskFreeSpaceExW`.

**roots:** `GetLogicalDrives` и `GetDriveTypeW` (быстро). Метки и место (`GetVolumeInformationW`, `GetDiskFreeSpaceExW`) запрашиваются параллельно, по потоку на диск, с таймаутом 1,5 с. Отключённые сетевые диски не блокируют выдачу.

**open_read:** `std::fs::File` (verbatim) с `FILE_FLAG_SEQUENTIAL_SCAN`.

**Скрытые:** запись скрыта, если стоит `HIDDEN` (включая `HIDDEN|SYSTEM`). Dotfiles скрыты только при `dotfiles_hidden_on_windows`.

### 3.2 macOS

- **Открытие:** `open(dir, O_RDONLY|O_DIRECTORY|O_CLOEXEC)`.
- **Чтение:** `getattrlistbulk(fd, &attrlist, buf[256 КБ], len, FSOPT_PACK_INVAL_ATTRS | FSOPT_NOFOLLOW)`.
  - `commonattr = ATTR_CMN_RETURNED_ATTRS | ATTR_CMN_NAME | ATTR_CMN_OBJTYPE | ATTR_CMN_MODTIME | ATTR_CMN_FLAGS | ATTR_CMN_ACCESSMASK`
  - `fileattr = ATTR_FILE_DATALENGTH`
  - Возвращает число записей, 0 — конец.
- **Разбор:** записи идут подряд, каждая начинается с `u32 length`. Атрибуты в порядке битов. `attrreference_t` даёт имя (UTF-8, NFD как есть).
  - `MODTIME` → `timespec`.
  - `FLAGS & UF_HIDDEN` → `HIDDEN`.
  - `ACCESSMASK & 0o111` → `EXEC`.
  - `OBJTYPE`: `VREG`/`VDIR`/`VLNK`.
  - Для `VLNK` при `resolve_links` выполняется `fstatat(fd, name, 0)`: `LinkDir`/`LinkFile`, ошибка `ENOENT` → `LinkBroken`.
- **Скрытые:** `DOTFILE` (имя на `.`) или `UF_HIDDEN`.
- **Fallback:** `std::fs::read_dir` + `symlink_metadata`, если вернулся `ENOTSUP` (часть FUSE/SMB).
- **Прочее:** `stat` — `fstatat` + `getattrlist(ATTR_CMN_CRTIME)` для btime. `space` — `statfs`. `roots` — `getfsstat(MNT_NOWAIT)` с фильтром `MNT_DONTBROWSE`, плюс `/`.

### 3.3 Linux (tier 2)

- **Открытие:** `rustix::fs::openat(CWD, dir, O_RDONLY|O_DIRECTORY|O_CLOEXEC)`.
- **Чтение имён:** `RawDir::new(fd, buf)` (`getdents64`), буфер 64 КБ на первый вызов, затем 256 КБ. `d_type` сразу даёт тип (`DT_UNKNOWN` → по `statx`).
- **Метаданные:** `statx(fd, name, AT_SYMLINK_NOFOLLOW | AT_STATX_DONT_SYNC, STATX_TYPE|STATX_MODE|STATX_SIZE|STATX_MTIME)`.
  - До 8k записей вызовы последовательны в потоке листинга.
  - Если `getdents` уже вернул больше 8k имён, батч режется на 4 части и обрабатывается в `std::thread::scope` (4 потока, переиспользуются на весь листинг). Порядок внутри батча сохраняется.
  - Первый батч (≤256 имён) всегда синхронный, ради первых строк.
- **Ссылки:** `statx` с follow для `S_IFLNK` → `LinkDir`/`LinkFile`/`LinkBroken`.
- **Скрытые:** `DOTFILE`. `EXEC` берётся из `mode & 0o111`.
- **Fallback:** `std::fs::read_dir`, если ядро без `statx` (<4.11): `fstatat`.
- **Прочее:** `space` — `statvfs`. `roots` — разбор `/proc/self/mountinfo` с фильтром псевдо-ФС.

## 4. Сортировка и фильтры

### 4.1 Представление

```rust
#[repr(C)] #[derive(Copy, Clone)]
pub struct SortRec {        // 24 байта
    pub prefix: u64,        // 8 байт сложенного имени/расширения, big-endian → сравнение как u64
    pub aux: u64,           // size | (mtime как u64 со сдвигом знака) | 0
    pub idx: u32,
    pub group: u8,          // 0 = dir-like (при dirs_first), 1 = прочее
    pub flags: u8,          // HIDDEN_EFFECTIVE, ESCAPED
    _pad: u16,
}
pub struct NameArena { bytes: Vec<u8>, ends: Vec<u32> }   // только во время загрузки
pub trait Names { fn name(&self, idx: u32) -> &str; }      // impl для NameArena и &[Entry]

pub fn arrange(n: &impl Names, recs: &mut Vec<SortRec>, spec: &ArrangeSpec) -> Vec<u32>; // filter → sort → order
pub fn natural_cmp(a: &str, b: &str) -> Ordering;
pub fn prefix_key(name: &str, natural: bool) -> u64;
```

### 4.2 Компаратор

Порядок сравнения:
1. `group`, если `dirs_first`. Направление `desc` на группу не влияет: каталоги всегда сверху, как в Far.
2. Первичный ключ:
   - Name: `prefix`, затем `natural_cmp`.
   - Ext: `prefix` от `ext()`, затем `natural_cmp(ext)`, затем имя.
   - Size / Mtime: `aux`, затем имя.
3. Финальный tie-break — сырые байты имени (детерминизм).
4. `desc` инвертирует шаги 2–3.

**natural_cmp:** итерация по байтам двух строк.
- ASCII: `to_ascii_lowercase`.
- Цифровая группа: пропустить ведущие нули, сравнить длину, затем цифры. При равенстве меньше нулей идёт первым.
- Не-ASCII символ: декодировать char, `fold(c)` = простой lowercase (только если результат один char и тоже не-ASCII), затем сравнить кодпоинты. Исключение: `ё`/`Ё` сравнивается как `е` + ε.

**prefix_key:**
- Сложенные ASCII-байты, пока не встретился первый спецслучай.
- Цифра в natural-режиме: записать `b'0'` и остановиться.
- Не-ASCII байт: записать `0x80` и остановиться.
- Остаток заполняется `0x00`.

Ключ монотонен относительно `natural_cmp` (доказывается proptest'ом), поэтому равенство префиксов означает «смотри дальше», а неравенство окончательно.

**Unsorted:** `order` — отфильтрованная identity.

### 4.3 Параллельность и стоимость

- Построение `SortRec` из `&[Entry]`: `par_iter` при n ≥ 32k.
- Сортировка: `sort_unstable_by` при n < 16k, иначе `par_sort_unstable_by` (глобальный rayon). Стабильность не нужна: tie-break полный.
- Фильтр: `Mask::matches` + hidden-предикат применяются **до** сортировки. При n ≥ 32k фильтр идёт через `par_iter().filter()`.
- Быстрый фильтр при наборе символа пересчитывается целиком: 100k ≈ 3–5 мс, кэш не нужен.
- Повторная сортировка той же key с `desc` (инверсия): `order.reverse()` с учётом групп, без сравнений.

## 5. Watcher, debounce, патчи, кэш

### 5.1 Типы

```rust
#[derive(Copy, Clone, Eq, PartialEq, Hash, Debug)] pub struct WatchId(u64);
pub enum WatchEvent {
    Added(CompactString, Option<Entry>),        // Entry есть у Windows Ex-событий
    Removed(CompactString),
    Modified(CompactString, Option<Entry>),
    Renamed { from: CompactString, to: CompactString, entry: Option<Entry> },
    Overflow,                                   // буфер переполнен → Rescan
    Gone,                                       // сам каталог удалён/недоступен
}
#[derive(Clone)] pub struct WatchTx { /* Sender<(WatchId, WatchEvent)> */ }
pub struct WatchGuard { /* Drop → снять наблюдение */ }

pub enum DirChange {                           // выход debounce
    Names { added: Vec<Entry>, changed: Vec<Entry>, removed: Vec<CompactString>, unresolved: Vec<CompactString> },
    Rescan,
    Gone,
}
```

### 5.2 Backend'ы

**Windows:**
- Открытие: `CreateFileW(dir, FILE_LIST_DIRECTORY, share all, OPEN_EXISTING, FILE_FLAG_BACKUP_SEMANTICS|FILE_FLAG_OVERLAPPED)`, затем `CreateIoCompletionPort`.
- Подписка: `ReadDirectoryChangesExW(h, buf 64 КБ, FALSE, FILE_NOTIFY_CHANGE_FILE_NAME|DIR_NAME|SIZE|LAST_WRITE|ATTRIBUTES, null, &ov, None, ReadDirectoryNotifyExtendedInformation)`. 64 КБ — лимит SMB.
- Поток: один `spawn_dedicated("vfs-watch")` на `GetQueuedCompletionStatusEx`. Управление (add/remove/stop) идёт через `PostQueuedCompletionStatus`.
- Из `FILE_NOTIFY_EXTENDED_INFORMATION` готовый `Entry` строится без stat. Тег reparse берётся из `ReparsePointTag`.
- Completion с 0 байт → `Overflow`. `ERROR_ACCESS_DENIED`/`ERROR_NOTIFY_CLEANUP` при удалении каталога → `Gone`.
- На ОС без Ex (<1709) используется `ReadDirectoryChangesW` (без Entry, имена резолвит `stat_entry`).
- `ERROR_INVALID_FUNCTION`/`ERROR_NOT_SUPPORTED` → `VfsError::Unsupported` → polling.

**macOS:** `notify::RecommendedWatcher` (FSEvents, file-level events), `RecursiveMode::NonRecursive`. События вне каталога отбрасываются по parent. `Flag::Rescan`/`MustScanSubDirs` → `Overflow`.

**Linux:** `notify` (inotify), `NonRecursive`. `IN_Q_OVERFLOW` → `Overflow`. Ошибка `ENOSPC` (исчерпан `max_user_watches`) → polling.

**Polling:**
- Раз в `max(poll_interval, 10 × время последнего листинга)` перечитывается каталог, и вычисляется дифф по именам, размеру и mtime.
- Только для видимых табов, никогда для фоновых.

### 5.3 WatchHub и debounce

Один поток `vfs-watch-hub` (dedicated) получает `(WatchId, WatchEvent)` из backend'ов. Состояние на каждый watch: `FxHashMap<name, Pending>`, `t_first`, `t_last`.

Алгоритм:
- Flush происходит в `min(t_last + debounce_ms, t_first + max_latency_ms)`. Ожидание — `crossbeam::select!` с `recv_deadline`.
- Коалесцирование по имени: Added+Removed → ничего; Removed+Added → Modified; Renamed = Removed(from) + Added(to).
- Больше 4096 имён в окне или `Overflow` → `Rescan`.
- Шторм: 3 flush подряд упёрлись в max_latency → режим «только Rescan» не чаще 1 раза в секунду. Выход из режима — после 2 с тишины.
- Flush отправляет `msg("vfs.dir_changed", …)` с `CancelToken` хаба. В `apply` (UI-поток):
  1. Найти таб по `(TabId, Gen)` подписки. Нет таба или gen изменился → снять watch.
  2. `Gone` → `panel.refresh` (core сам поднимется к существующему родителю при Failed).
  3. `Rescan` или `entries.len() < patch_threshold` → `cx.dispatch(panel.refresh{tab})`.
  4. Иначе → задача патча (5.4).

Жизненный цикл:
- Watch ставится в `load` после `Done` для `(tab, gen)`, только если таб видим (запрос №4).
- `Hidden` → снять watch и пометить таб dirty. `Shown` → если dirty, то `panel.refresh`.
- `Closed` → снять watch.
- Свои изменения (S5) специально не подавляются: S5 шлёт `panel.refresh`, повторное событие схлопнется debounce'ом или даст пустой патч.

### 5.4 Инкрементальный патч (каталоги ≥ patch_threshold)

1. На Interactive-полосе разрешаются `unresolved` и `Modified` без `Entry` через `stat_entry`. Если не найдено → removed.
2. На cpu-pool:
   - Берётся `DirIndex` (`FxHashMap<CompactString, u32>`), кэш на `(tab, gen, len)`. Строится лениво из `Arc<Vec<Entry>>` за ≈5 мс на 100k и инкрементально обновляется самим патчем.
   - Строится `Patch` (запрос №2):
     - `update` — существующие имена;
     - `remove` — индексы по убыванию;
     - `append` — новые;
     - `order` — пересчёт. Удалённые выбрасываются, индексы переназначаются по той же последовательности `swap_remove`, новые/изменённые вставляются бинарным поиском компаратором текущей сортировки. Итог O(n + k log n).
3. Отправка `listing_msg(Patch{ base_len, seq })`. Если core отбросил патч (len/seq не совпали), следующий flush делает `panel.refresh`.

### 5.5 Кэш каталогов

- `DirCache`: `Mutex<LruMap<Location, CachedDir>>`, лимиты `cache_dirs` и `cache_entries` (≈10–14 МБ при 200k).
- `CachedDir { entries: Arc<Vec<Entry>>, at: Instant, fresh: Arc<AtomicBool>, watch: Option<WatchGuard> }`.
- Наполнение: `TabEvent::Left { loc, entries }` (запрос №4) передаёт Arc от core, копирования нет.
- Свежесть:
  - Локальный каталог держит watch в кэше (≤8 watch'ей для кэша, LRU). Любое событие сбрасывает `fresh`.
  - Сетевые/UNC/removable не наблюдаются, всегда stale.
- Hit fresh → листинг без I/O. Hit stale → кэш, `Done`, затем `panel.refresh` (double-buffer, курсор и выделение по именам).
- Removable-тома в кэше не держат watch и не держат handle.

### 5.6 Асинхронный размер каталогов

- Команда `vfs.dir_size { all?: Bool }` (namespace `vfs`, handler из S4). Цели: выделенные каталоги, иначе каталог под курсором, при `all` — все каталоги таба.
- Выполняется как Job: `JobRegistry::start(JobSpec{kind:"dir_size", lane: Interactive})`. Прогресс (`items_done`, `bytes_done`) пишется в атомики, отмена через `job.cancel`.
- Обход:
  - Пул `dir_size_threads` потоков (`spawn_dedicated`, общий `crossbeam_deque::Injector` каталогов).
  - Используются те же `ListStream` (на Windows и macOS размер приходит из листинга, на Linux через `statx` с маской `STATX_SIZE`).
  - Reparse и symlink не обходятся, их размер 0. Cloud-placeholders учитываются по логическому размеру без гидрации.
  - На Unix хардлинки дедуплицируются по `(dev, ino)` при `nlink > 1`.
- Тип тома для выбора числа потоков: Windows — `IOCTL_STORAGE_QUERY_PROPERTY(StorageDeviceSeekPenaltyProperty)`, macOS/Linux — признак rotational (`/sys/block/*/queue/rotational`), сеть → 1 поток.
- Результат: раз в 100 мс и в конце отправляется `Patch.update` с `size` и флагом `Attrs::SIZE_KNOWN` (запрос №5). Если активна сортировка по размеру, в патч входит пересчитанный `order`.

### 5.7 Иконки

```rust

pub fn icon_class(name: &str, kind: EntryKind, attrs: Attrs) -> IconClass;
```

## 7. Бенчи и целевые цифры

**Стенд:**
- Windows-ноут, NVMe: NTFS и Dev Drive ReFS. Плюс SMB-шара в локальной сети.
- Mac Apple Silicon: APFS.
- VMware Linux: ext4 и btrfs.

Release, профиль `profiling`. Прогоны: warm (повтор) и cold. Cold-кэш сбрасывается так: Windows — `RAMMap -Et` или переподключение VHDX; macOS — `sudo purge`; Linux — `echo 3 > /proc/sys/vm/drop_caches`.

**criterion:** `list.rs` (стрим без core), `sort.rs` (`SortRec` build, sort Name/Ext/Size natural, filter, `natural_cmp` на парах, `prefix_key`), `patch.rs` (100 изменений в 100k).

## 9. Запросы к S0

1. **Чанк с порядком.** `ListingUpdate::Chunk(Vec<Entry>)` → `Chunk { entries: Vec<Entry>, visible: Vec<u32> }`. Core дописывает `visible` (абсолютные индексы) в `order` через `Arc::make_mut`.
   Причина: иначе на каждый чанк нужно слать полный `Order` (O(n) копирование, на 1M это ≈1 ГБ memcpy за загрузку).
2. **Инкрементальный патч.**
   ```rust
   ListingUpdate::Patch(Patch)
   pub struct Patch {
       pub base_len: u32,
       pub seq: u32,
       pub update: Vec<(u32, Entry)>,
       pub remove: Vec<u32>,       // по убыванию, применять swap_remove
       pub append: Vec<Entry>,
       pub order: Arc<Vec<u32>>,
   }
   ```
   Core при `gen`, `len` и `seq` совпадают:
   - применяет update (поправить bytes выделения);
   - применяет remove (снять бит, перенести бит перенесённого последнего элемента);
   - применяет append, ставит `order`;
   - инкрементально правит stats;
   - удерживает курсор на той же записи (иначе клампит);
   - применяет `pending_focus` к добавленным.
   Иначе патч отбрасывается.
   Нужен для watcher'а в больших каталогах и для размеров папок.
3. **Последовательность arrange.** `ArrangeReq.seq: u32` и `LoadReq.seq`, `Order { order, for_len, seq }`. Core увеличивает `Listing.arrange_seq` при каждом `panel.sort`, `filter` и `hidden.toggle`, а `Order`/`Patch` со старым `seq` отбрасывает.
   Причина: два быстрых `panel.sort` подряд могут вернуться в обратном порядке, `for_len` это не ловит.
4. **События табов для S4.** `ListingService::tab_event(&self, ev: TabEvent)`:
   ```rust
   enum TabEvent {
       Shown(TabId), Hidden(TabId), Closed(TabId),
       Left { tab: TabId, loc: Location, entries: Arc<Vec<Entry>> },
   }
   ```
   Когда вызывается:
   - `Left` — при навигации или refresh-swap до замены листинга;
   - `Shown`/`Hidden` — при смене активного таба панели и `panel.toggle`;
   - `Closed` — при `tab.close`.
   Нужно для watch только видимых каталогов и для кэша без копирования.
5. **Новые биты `Attrs`.** `ESCAPED_NAME = 1 << 10` (имя экранировано, реальное имя даёт `vfs::name::to_os`) и `SIZE_KNOWN = 1 << 11` (у каталога `size` валиден). S2 показывает `<DIR>` или размер по `SIZE_KNOWN`, S5 обязан строить пути через `vfs::name::join_os`.
6. **Правила нормализации `Location::local`.** Зафиксировать в core (S4 даст эталонную `normalize_local` для тестов):
   - абсолютный путь;
   - `\\?\C:\` → `C:\`, `\\?\UNC\s\sh` → `\\s\sh`;
   - буква диска в верхнем регистре;
   - `/` → `\` на Windows;
   - `.` и `..` разрешены лексически;
   - без завершающего разделителя, кроме корня;
   - регистр имён не трогается;
   - symlink не раскрываются.
   Иначе `C:\x` и `c:/x/` дадут два разных кэша и истории.

## 10. Решения для владельца

1. **Размер папок в панели.** Автоподсчёт удобен (видно, что занимает место), но на HDD и сетевых дисках нагружает I/O и шумит.
   - Варианты:
     - (а) только по команде (`vfs.dir_size`, выделенные или под курсором);
     - (б) автоматически для локальных SSD, по команде на остальных;
     - (в) всегда автоматически.
   - Рекомендация: **(а)** по умолчанию, (б) как опция в `[vfs]`.
2. **Иконки файлов.** Системные иконки привычны, но медленнее (вызовы Shell/COM), выглядят по-разному на ОС и не вписываются в стиль DN/Far.
   - Варианты:
     - (а) свой набор по классам (≈15 классов, единый стиль, офлайн);
     - (б) системные по расширению (кэш на расширение);
     - (в) без иконок, только цвет и раскраска по маскам, как в Far.
   - Рекомендация: **(а)**, (в) включается отдельным режимом. (б) — позже, если попросят.
3. **Что считать скрытым на Windows.** В Windows скрытость задаётся атрибутом, но многие разработчики ожидают, что `.git` и `.env` тоже прячутся.
   - Варианты:
     - (а) только атрибут Hidden, как Explorer;
     - (б) атрибут Hidden и имена на точку.
   - Рекомендация: **(а)** по умолчанию, (б) включается опцией `dotfiles_hidden_on_windows`.
4. **Мгновенный показ ранее открытого каталога.** При возврате в каталог можно сразу показать запомненный список и тут же тихо обновить его (на долю секунды возможен устаревший вид) или всегда ждать свежего чтения.
   - Варианты:
     - (а) показывать запомненное и обновлять (для наблюдаемых локальных каталогов он и так актуален);
     - (б) всегда свежее чтение.
   - Рекомендация: **(а)**.
5. **Порядок имён по умолчанию.** Natural sort ставит `file2` раньше `file10` (как Explorer и Finder). Классический Far сортирует посимвольно (`file10` раньше `file2`).
   - Варианты:
     - (а) natural по умолчанию с опцией выключить;
     - (б) посимвольно по умолчанию (как Far) с опцией включить.
   - Рекомендация: **(а)**.
