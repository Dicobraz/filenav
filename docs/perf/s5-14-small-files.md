# S5-14: мелкие файлы — системная копия или свой путь

Бенч #3 (S5 §7), `bench_small_files` в `crates/ops/src/ops/copy_tests.rs`:

```
cargo nextest run --release -p urfin-ops bench_small --run-ignored only --no-capture
```

Стенд владельца: Windows 11, сборка 26300, NVMe, Defender (защита в реальном
времени включена); 10 000 файлов 1–64 КиБ (333 МБ), данные в кэше ОС, один и
тот же каталог-источник, назначение — тот же том. 5 раундов, медиана (файлов/с):

| Движок | 1 поток | 8 потоков |
|---|---:|---:|
| `CopyFileExW` (сейчас) | 2209 | 3525 |
| `CopyFile2` без колбэка | 2045 | 3270 |
| свой путь (§4.2: файл целиком, `CREATE_NEW`, потоки, `FileBasicInfo` последним) | 1956 | 1898 |

Разброс большой (минимумы: `CopyFile2` ×1 — 312, свой ×1 — 33): фоновая
активность Defender. Первый прогон (3 раунда) давал свой ×1 — 141, ×8 — 1519.

**Вывод и порог.** Свой путь не быстрее системного ни в одном режиме, в 8
потоков — на 45 % медленнее. По правилу S5 §4.2 («own ≤ CopyFile2 + 10 % —
по умолчанию системный») по умолчанию — системная копия. Вероятная причина:
`CopyFile*` на Windows 11 24H2+ сообщает фильтрам антивируса, что это копия
(«copy file notifications»), и Defender не пересканирует данные; своя
запись — обычная, сканируется целиком.

`CopyFile2` в пределах шума от `CopyFileExW` — переход не даёт выигрыша; движок
`Os` остаётся на `CopyFileExW` (колбэк с паузой, отменой и прогрессом уже есть,
потоки ADS — Zone.Identifier — копируются).

Свой путь оставлен под `[ops.strategy] small = "own"` (для дисков без
антивируса, Dev Drive — проверить в S5-19); он тоже сохраняет Zone.Identifier
(тест `copy_keeps_zone_identifier_both_engines`). Порог «мелкого» файла —
`[ops] small_file` = 1 МиБ, без изменений.
