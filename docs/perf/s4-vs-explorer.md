# Urfin против Проводника (S4-19)

Снято 2026-10-18 на стенде владельца (Windows 11 Pro 26H2, NTFS, NVMe), warm — повторные открытия того же каталога. Каталог: `gen_tree --n 100000 --seed 1` — 99 462 записи, из них 1 906 скрытых.

## Протокол

Вместо записи экрана (S4 §7) — UI Automation, без вмешательства в ввод: скрипт открывает окно Проводника на каталоге (`explorer.exe <путь>`) и опрашивает его дерево UIA каждые ~20 мс:
- **первые строки** — появился первый `ListItem` списка;
- **полный список** — текст строки состояния «Элементов: N» дошёл до итога.

Проводник не показывает скрытые файлы, поэтому итог у него 97 556, а не 99 462. Окно закрывается через `WindowPattern.Close`. 5 прогонов, медиана. Сам опрос UIA добавляет к Проводнику десятки миллисекунд, на фоне секунды это несущественно.

Urfin — `vfs_bench --core-only` (тот же каталог, `VfsListing` и core, без окна): от `panel.go` до первых строк в табе и до `Complete` с финальным порядком.

## Результат

| | Проводник | Urfin | Во сколько раз |
|---|---|---|---|
| первые строки | 1156 мс | 1,5 мс | ×770 |
| полный список | 1219 мс | 56 мс (с сортировкой natural, каталоги сверху) | ×22 |

Цель S4 §7 «≥ 5× быстрее до полного списка» — выполнена.

Для справки, CLI на том же каталоге: `cmd /c dir /b /a` — 400 мс, `Get-ChildItem -Force` — 1737 мс. На 1M (994 829 записей) `dir /b /a` — 4,0 с, Urfin — 0,8 с.

## Как повторить

```
cargo run -p urfin-testdata --example gen_tree --release -- --n 100000 --seed 1 --out %TEMP%\urfin-bench-gen-100k
cargo run -p urfin-vfs --example vfs_bench --release -- %TEMP%\urfin-bench-gen-100k --runs 7 --core-only
```

Скрипт замера Проводника (PowerShell 5.1, ASCII): ищет окно `CabinetWClass` с именем каталога, ждёт первый `ListItem` и текст вида `…: N` с ожидаемым N. Переменные PowerShell без учёта регистра — не называть цикл `$t` при `$T = [TreeScope]`.
