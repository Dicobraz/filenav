# S5-16: крупные файлы

Бенч #5 (S5 §7), `bench_large_file` в `crates/ops/src/ops/copy_tests.rs`:

```
cargo nextest run --release -p urfin-ops bench_large --run-ignored only --no-capture
```

Стенд владельца: NVMe WD PC SN5000S 512 ГБ (QLC), Windows 11 26300. На момент
замера свободно ~27 ГБ из 477 (до чистки кэша сборки — 6,5 ГБ). Файл 4 ГиБ на
том же томе; время — до `FlushFileBuffers` копии включительно; 3 раунда (МиБ/с):

| Раунд | `CopyFileExW` с кэшем | `COPY_FILE_NO_BUFFERING` |
|---|---:|---:|
| 0 | 60 | 74 |
| 1 | 92 | 106 |
| 2 | 115 | 105 |

**Это скорость устройства, а не движка.** У QLC-накопителя SLC-кэш динамический
и зависит от свободного места; на почти полном диске запись идёт с родной
скоростью QLC (~100 МиБ/с). Оба режима упираются в один потолок — свой
небуферизованный overlapped-движок (§4.3: кольцо 4×8 МиБ, диапазоны) на этом
стенде выигрыша показать не может, и мерить его — гигабайты записи на SSD
владельца на каждый прогон.

**Решение S5-16.** Файлы от `[ops] large_file` (256 МиБ) — `CopyFileExW` с
`COPY_FILE_NO_BUFFERING`: та же скорость, но гигабайты копии не вытесняют
кэш ОС (отзывчивость системы и Urfin во время копии). Кольцо и диапазонный
режим (§4.3) — когда появится стенд со свободным быстрым диском (S5-19/S5-25,
перф-проход по носителям).

Приёмка: нечётные размеры (0, 1, 511/512/513, 4095/4096/4097, 1 МиБ ± 1) мимо
кэша идентичны — `unbuffered_odd_sizes_are_identical`; пауза ≤ 100 мс —
`unbuffered_pause_within_100ms` (колбэк между чанками). 4 ГиБ + 1 — только
в бенче вручную.
